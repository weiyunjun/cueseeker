# CueSeeker Logs

This directory stores local development diagnostics generated by the native app.

Search timing logs are only written when `CUESEEKER_PERF_SEARCH`,
`CUESEEKER_PERF_UI`, or `CUESEEKER_PERF` is enabled:

```text
logs/search-timing/search-timing-YYYY-MM-DD.log
```

Search end-to-end JSON events are written to:

```text
logs/search-e2e/search-e2e-YYYY-MM-DD.jsonl
```

Each Search event is written on one readable line so timing from different
development machines can be compared directly from the project folder or pasted
into an AI debugging session.

Example:

```text
2026-05-11 19:48:00.100 +08:00 run=2 sequence=17 event=db.fts_batch elapsed=713.02ms phase=420.31ms queryLength=2 offset=0 limit=1000 appending=false debounce=true folders=1 batch=1 candidateOffset=0 candidateBatchLimit=2000 candidates=1428
```

Each Search E2E JSONL line keeps the benchmark table fields at the top level:
`query`, `warmupMilliseconds`, `returned`, `totalCount`, `fileSummaries`,
`hotAvgMilliseconds`, and `hotRawMilliseconds`. The rolling benchmark fields
use `elapsedMilliseconds` as the client end-to-end metric. The same record also
keeps `databaseMilliseconds`, UI timing breakdowns, rendered counts, and small
result/file-summary samples for orientation.

Example `search_status_completed` line:

```json
{"schemaVersion":2,"timestamp":"2026-05-15 15:09:57.438 +08:00","sequence":51,"runID":1,"event":"search_status_completed","query":"世界","benchmarkMetric":"elapsedMilliseconds","warmupMilliseconds":602.6,"returned":100,"totalCount":2078,"fileSummaries":84,"hotAvgMilliseconds":null,"hotRawMilliseconds":[],"currentRunKind":"warmup","currentRunMilliseconds":602.6,"hotRunCount":0,"hotTargetRunCount":5,"hasMore":true,"offset":0,"limit":100,"groups":84,"renderedRows":100,"databaseMilliseconds":579.74,"elapsedMilliseconds":602.6,"firstVisibleMilliseconds":null,"status":"completed"}
```
