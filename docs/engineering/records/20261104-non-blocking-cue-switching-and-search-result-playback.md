# Non-Blocking Cue Switching and Search Result Playback

- **Date**: 2026-11-04
- **Requirement**: `docs/human/requirements/20261104-Bug-Non-Blocking Cue Switching And Search Result Playback.md`
- **Scope**: Native playback in-session seek & rapid seek coalescing (`SFXNativePlaybackSession`, `SFXNativePlaybackPlayer`, `PlaybackPlayer`), large search result playback entry & playlist/navigation indexing (`SearchStore`, `AppCoordinator+PlaybackPlaylist`, `AppCoordinator+Search`, `WorkbenchSearchView`), and playback-covered Workbench/Search invalidation & metadata/subtitle reuse (`PlaybackStore`, `ContentView`, `WorkbenchWorkspaceView`, `AppCoordinator`, `AppCoordinator+Playback`, `AppCoordinator+Excerpt`)

## Summary

1. **Non-Blocking In-Session Seek & Rapid Seek Coalescing (`SFXNativePlaybackSession`, `SFXNativePlaybackSession+AudioAndDecode`, `SFXNativePlaybackPlayer`, `PlaybackPlayer`)**:
   - Changed `requestSeekToMilliseconds:...` in `SFXNativePlaybackSession` so all non-recovery in-session seeks (`!rebuildsAudioOutput`) enqueue asynchronously on the decode loop without waiting on `_packetQueueCondition` on the main thread, immediately updating presentation generation, `_audioResetInProgress`, pause/segment boundary state, and exposed `_currentTime` at request time.
   - Checked `[self hasPendingSeekRequestLocked]` inside `handleVideoPacket:`'s `avcodec_receive_frame` loop and guarded `_currentTime` / `_lastSubmittedVideoFrameMilliseconds` updates so pre-seek decoded frames abort immediately when a newer seek arrives and cannot overwrite `_currentTime`.
   - Updated `applyInSessionSeekToSeconds:...` to detect when a newer seek arrived while `stopReadAheadLoop` or `av_seek_frame` was running (`supersededByNewerSeek = _seekRequestPending`), skipping redundant read-ahead startup and audio drain so rapid consecutive seeks coalesce to the latest target timestamp.
   - Updated `PlaybackPlayer.beginPresentationTransition` so a rapid `.preserve` seek arriving before an earlier uncommitted `.replace` subtitle transition preserves `.replace` with `initialTimestampMilliseconds` retargeted to the new timestamp, and added `PlaybackPlayer.currentSubtitleURL`.
2. **On-Demand Search Result Playback Entry Under Large Result Sets (`SearchStore`, `AppCoordinator+PlaybackPlaylist`, `AppCoordinator+Search`, `WorkbenchSearchView`)**:
   - Added `loadedSearchResultCount`, `loadedSearchResult(forCueID:fallbackRank:)`, `loadedSearchResult(at:)`, and O(1) `loadedSearchResultIndex(forCueID:)` to `SearchStore`.
   - Updated `synchronizeSearchAndPlaylistOnPlayback`, `installSearchPlaybackPlaylistSource`, `refreshSearchPlaybackPlaylistSource`, `searchPlaylistItemProvider`, `updateSearchNavigationSnapshotForOpenedResult`, `loadedSearchNavigationSnapshot`, and `WorkbenchSearchView.play` to operate on `loadedSearchResultCueIDs` and resolve only the opened cue and bounded navigation window on demand instead of materializing `search.searchResults`.
3. **Playback-Covered Workbench Invalidation Isolation & Same-Video Metadata/Subtitle Reuse (`PlaybackStore`, `SearchStore`, `ExcerptStore`, `LibraryStore`, `ContentView`, `WorkbenchWorkspaceView`, `AppCoordinator`, `AppCoordinator+Playback`, `AppCoordinator+Excerpt`)**:
   - Introduced `PlaybackRouteVisibilityStore` (`playback.routeVisibility`) so `ContentRootView` and `WorkbenchWorkspaceView` observe only route/visibility state rather than high-frequency `PlaybackStore` mutations, and removed `@Published` from `SearchStore.selectedSearchResult`, `SearchStore.searchNavigationSnapshot`, `SearchStore.isPlaybackPruningActive`, `ExcerptStore.selectedExcerpt`, and `LibraryStore.selectedLibraryVideo`.
   - Updated `playbackDisplayTitle` to reuse non-empty `knownDisplayTitles` (`providedDisplayTitle`, `selectedSearchResult.displayTitle`, `selectedExcerpt.displayTitle`) before querying SQLite.
   - Updated `play(_ result: SubtitleSearchResult)` and `play(_ excerpt: Excerpt)` so in-session seeks within the already-open video reuse the active video codec/decode mode and, when `player.currentSubtitleURL` matches the target subtitle file, reuse the loaded subtitle source without re-querying SQLite or re-reading the subtitle file from disk.
4. **Verification**:
   - Added `nativeRapidConsecutiveInSessionSeeksCoalesceToFinalTargetWithoutBlocking` in `NativePlaybackMediaTimelineTests` and `switchingCuesDuringPlaybackDoesNotRefreshCoveredSearchOrWorkbenchChrome` & `openingSearchResultUnderLargeOrderedCueListResolvesPlaylistAndNavigationOnDemand` in `CueGroupRefreshScopeIntegrationTests`.
