# Non-Blocking Cue Switching and Search Result Playback

- **Date**: 2026-11-04
- **Requirement**: `docs/human/requirements/20261104-Bug-Non-Blocking Cue Switching And Search Result Playback.md`
- **Scope**: Native playback in-session seek & rapid seek coalescing (`SFXNativePlaybackSession`, `SFXNativePlaybackPlayer`, `PlaybackPlayer`), large search result completion & playback entry (`CueContentStore`, `SearchStore`, `SearchStore+Execution`, `SubtitleTableRowModelStore`, `AppCoordinator+PlaybackPlaylist`, `AppCoordinator+Search`, `WorkbenchSearchView`), playback-covered Workbench/Search invalidation, persistent database connection & multi-episode video metadata reuse (`PlaybackStore`, `PlaybackViewModel`, `PlaybackChromeTrackingView`, `ContentView`, `WorkbenchWorkspaceView`, `AppCoordinator`, `AppCoordinator+Playback`, `AppCoordinator+PlaybackAudioTrack`, `AppCoordinator+PlaybackLibraryChange`, `AppCoordinator+Excerpt`, `AppCoordinator+Library`), and lexical media path normalization & background playback file availability precheck (`WebDAVSupport`, `PlaybackTypes`, `AppCoordinator`, `AppCoordinator+Playback`, `AppCoordinator+Excerpt`, `AppCoordinator+Library`)

## Summary

1. **Non-Blocking In-Session Seek, Audio-Prime Bypass & Rapid Seek Coalescing (`SFXNativePlaybackSession`, `SFXNativePlaybackSession+AudioAndDecode`, `SFXNativePlaybackPlayer`, `PlaybackPlayer`)**:
   - Changed `requestSeekToMilliseconds:...` in `SFXNativePlaybackSession` so all non-recovery in-session seeks (`!rebuildsAudioOutput`) enqueue asynchronously on the decode loop without waiting on `_packetQueueCondition` on the main thread, immediately updating presentation generation, `_audioResetInProgress`, pause/segment boundary state, and exposed `_currentTime` at request time.
   - Checked `[self hasPendingSeekRequestLocked]` inside `handleVideoPacket:`'s `avcodec_receive_frame` loop and guarded `_currentTime` / `_lastSubmittedVideoFrameMilliseconds` updates so pre-seek decoded frames abort immediately when a newer seek arrives and cannot overwrite `_currentTime`.
   - Updated `applyInSessionSeekToSeconds:...` to detect when a newer seek arrived while `stopReadAheadLoop` or `av_seek_frame` was running (`supersededByNewerSeek = _seekRequestPending`), skipping redundant read-ahead startup and audio drain so rapid consecutive seeks coalesce to the latest target timestamp.
   - Updated `waitUntilVideoFrameShouldRenderAtSeconds:isFirstFrameAfterOpen:` to bypass the audio-prime wait loop for the first post-open/seek video frame (`isFirstFrameAfterOpen`) so the target video frame renders immediately without blocking on audio buffer fill.
   - Updated `PlaybackPlayer.beginPresentationTransition` so a rapid `.preserve` seek arriving before an earlier uncommitted `.replace` subtitle transition preserves `.replace` with `initialTimestampMilliseconds` retargeted to the new timestamp, and added `PlaybackPlayer.currentSubtitleURL`.
2. **Background Pre-Assembly of Large Search Completion & On-Demand Search Result Playback (`CueContentStore`, `SearchStore`, `SearchStore+Execution`, `SubtitleTableRowModelStore`, `AppCoordinator+PlaybackPlaylist`, `AppCoordinator+Search`, `WorkbenchSearchView`)**:
   - Pre-assembled `SearchStorePrebuiltCompletion` (`cueIDs`, `contentByCueID`, `rankByCueID`, and `facetDistribution`) on the background `Task.detached` in `SearchStore.startSearch`, added `CueContentStore.installPrebuilt(_:publishesChange:)`, and updated `SubtitleTableRowModelStore.updateResidentSearchReferences` to emit `.append` when extending an already-projected first page so large result completions (e.g. 76k+ rows) commit on `@MainActor` without full-array re-iteration or table reload.
   - Added `loadedSearchResultCount`, `loadedSearchResult(forCueID:fallbackRank:)`, `loadedSearchResult(at:)`, and O(1) `loadedSearchResultIndex(forCueID:)` to `SearchStore`.
   - Updated `synchronizeSearchAndPlaylistOnPlayback`, `installSearchPlaybackPlaylistSource`, `refreshSearchPlaybackPlaylistSource`, `searchPlaylistItemProvider`, `updateSearchNavigationSnapshotForOpenedResult`, `loadedSearchNavigationSnapshot`, and `WorkbenchSearchView.play` to operate on `loadedSearchResultCueIDs` and resolve only the opened cue and bounded navigation window on demand instead of materializing `search.searchResults`.
3. **Playback-Covered Workbench Invalidation Isolation, Persistent `CueContentDatabase` & Multi-Episode Metadata/Subtitle Reuse (`PlaybackStore`, `PlaybackViewModel`, `PlaybackChromeTrackingView`, `SearchStore`, `ExcerptStore`, `LibraryStore`, `ContentView`, `WorkbenchWorkspaceView`, `AppCoordinator`, `AppCoordinator+Playback`, `AppCoordinator+PlaybackAudioTrack`, `AppCoordinator+PlaybackLibraryChange`, `AppCoordinator+Excerpt`)**:
   - Introduced `PlaybackRouteVisibilityStore` (`playback.routeVisibility`) so `ContentRootView` and `WorkbenchWorkspaceView` observe only route/visibility state rather than high-frequency `PlaybackStore` mutations, removed `@Published` from non-observed selection/navigation properties, and throttled `PlaybackViewModel` `@Published` progress updates during rapid cue switches and hover tracking.
   - Held a persistent `cueContentDatabase: CueContentDatabase?` on `AppCoordinator` and reused the library-membership check result across `synchronizeSearchAndPlaylistOnPlayback`, `installSearchPlaybackPlaylistSource`, and `openSearchResult` so cue switching never opens/closes temporary SQLite connections on the main thread.
   - Cached per-video playback metadata (`codec`, `defaultAudioTrackIndex`, and fallback `storedDisplayTitle`) by `mediaPath` across multiple episodes in `cachedVideoPlaybackMetadataByMediaPath` (invalidated on `indexedCueDataRevision` change, rename, auxiliary refresh, and `stopPlayback`), and reused the open video session and loaded subtitle source when seeking within the same video/subtitle file.
4. **Lexical Media Path Normalization & Background Playback File Availability Precheck (`WebDAVSupport`, `PlaybackTypes`, `AppCoordinator`, `AppCoordinator+Playback`, `AppCoordinator+Excerpt`, `AppCoordinator+Library`, `WorkbenchSearchView`)**:
   - Replaced `.standardizedFileURL.path` and 1-argument `URL(fileURLWithPath:)` in `URL.mediaPath`, `URL.standardizedMediaURL`, and `URL.fromMediaPath` with in-memory lexical path normalization (`URL.lexicallyNormalizedLocalFilePath`) and explicit `URL(fileURLWithPath: ..., isDirectory: ...)` so local and mounted-volume path conversions never issue synchronous `stat` / `realpath` filesystem calls on the main thread.
   - Moved the pre-playback video file existence (`FileManager.default.fileExists`) and subtitle readability (`FileManager.default.isReadableFile`) checks out of synchronous `@MainActor` execution into `schedulePlaybackOpen`'s background `Task.detached` when opening a new video or subtitle (`PrecheckedPlaybackMediaAvailability` and `PlaybackRequest(..., precheckedVideoFileExists:)`), preserving all missing-file error reporting and state behavior without blocking the UI thread on mounted or network volumes.
5. **Verification**:
   - Added `nativeRapidConsecutiveInSessionSeeksCoalesceToFinalTargetWithoutBlocking` in `NativePlaybackMediaTimelineTests`, `searchStorePrebuiltCompletionAppendsBeyondFirstPageWithoutFullTableReload` in `TableSandboxRowModelStoreTests`, and `switchingCuesDuringPlaybackDoesNotRefreshCoveredSearchOrWorkbenchChrome`, `openingSearchResultUnderLargeOrderedCueListResolvesPlaylistAndNavigationOnDemand` & `multiEpisodePlaybackMetadataCacheRetainsVisitedVideosAndPersistentCueContentDatabase` in `CueGroupRefreshScopeIntegrationTests`.
