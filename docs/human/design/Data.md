# Index流程

## 1. 视频与字幕匹配规则流程
这一步产生的匹配关系成为新的匹配关系，在Index流程前的匹配关系称为旧的匹配关系。

1. 找到同一文件夹下（不包含子文件夹）的所有字幕。
2. 每个字幕，最多只能匹配同一文件夹下（不包含子文件夹）的一个视频文件。
3. 去掉字幕文件的最后1个扩展名，尝试匹配所有去掉最后1个扩展名的完全匹配的视频。如果能，进入第8步；不能，进入第4步。
4. 去掉字幕文件的最后1个扩展名，尝试匹配所有到去掉最后2个扩展名的完全匹配的视频。如果能，进入第8步；不能，进入第5步。
5. 如果字幕文件不存在2个扩展名，匹配失败；如果字幕文件存在2个扩展名，进入第6步。
6. 去掉字幕文件的最后2个扩展名，尝试匹配所有到去掉最后1个扩展名的完全匹配的视频。如果能，进入第8步；不能，进入第7步。
7. 去掉字幕文件的最后2个扩展名，尝试匹配所有到去掉最后2个扩展名的完全匹配的视频。如果能，进入第8步；不能，匹配失败。
8. 一个字幕文件最多只能匹配一个视频文件。这一步处理匹配到的视频文件的优先级。此时只存在后缀名不同的情况，暂定为：.mkv > .mp4 > .webm > .flv > .avi > .mov。结束视频与字幕匹配规则流程。

## 2. 检测流程
1. 新的匹配关系中的文件（基于文件路径和文件名判定），不位于旧的匹配关系中，视为新文件。否则视为旧文件，进入第2步。
2. 检测并确定旧文件是否变化，依据是文件大小和修改时间戳。

## 3. 内部版本与数据完整性检查
1. 检查已有数据是否由当前算法版本生成，以及必要数据是否缺失。
2. 版本过期或数据缺失，重新生成对应数据。
3. 版本有效且数据完整，不重新生成对应数据。

## 4. 生成并发布核心Index数据
1. 更新新字幕文件或发生变化的旧字幕文件的信息：语言分析，Cue/CueGroup（详见/docs/human/design/Cue Parsing.md），播放结束数据、ASS 字体引用、ASS 分段缓存。
2. 发布文件身份、匹配关系、Cue等核心数据以及Search排序数据。
3. 数据库发布失败则回滚本次资料库的核心结果。

## 5. 更新视频元数据
更新新视频文件或发生变化的旧视频文件的相关信息：时长，分辨率，帧率，编码格式，音轨列表（按文件中的顺序，记录语言、标题、编码、声道数）。

## 6. 生成或检查自动封面
1. 如果当前为fallback封面，则尝试生成自动封面。生成成功切换为自动封面，生成失败维持现状。
2. 如果当前为用户自定义封面，则不修改封面。
3. 如果当前为自动封面，且视频文件是新视频文件，则尝试生成自动封面。生成成功切换为新的自动封面，生成失败使用fallback封面。
4. 如果当前为自动封面，且视频文件是旧视频文件，则尝试生成自动封面。生成成功切换为新的自动封面，生成失败回退到修改前，禁止用fallback封面覆盖已有自动封面。

## 7. 更新Library展示数据
1. 重建受影响文件夹的Library展示数据。
2. 重新计算Display Title。Display Title属于视频，为视频所在文件夹名与该视频在同文件夹视频中的序号，序号按该文件夹的视频数补零，至少2位。字幕、Cue与Excerpt的Display Title取其匹配视频的Display Title，显示Display Title的各处使用同一个值。

## 8. 完成Index并刷新 UI
结束Index流程。

## 失败处理
1. 扫描失败。例如NAS断开、权限失效、目录读取到一半失败。此时无法确定未扫描到的文件是真的消失，还是扫描不完整。这里应该立即取消本次Index流程并保留Index前状态。
2. 文件读取失败。已经知道文件存在，但暂时无法读取内容。只跳过该文件，保留该文件上一次成功Index的全部数据不影响其他文件结果的发布。
3. 字幕解析失败。文件存在且读取成功，但内容无法正确解析。只跳过该文件，保留该文件上一次成功Index的全部数据，不影响其他文件结果的发布。
4. 数据库发布失败。回滚本次资料库的全部结果，保留Index前状态。

## 注意事项
1. 第1步，匹配时处理扩展名大小写和 Unicode 规范化，保证 macOS、Windows 行为一致。
2. 第2步，对于视频文件被替换的情况（例如匹配关系中1.mov被1.mkv替换），根据规则被视为新文件，分配新的VideoID，观看进度，观看状态等自然会初始化。

# 永久身份与路径分离

数据库中的主要对象都有自己的永久 ID：

```text
LibraryID
 ├── VideoID
 ├── SubtitleID
 │    └── CueID
 │          └── ExcerptID
```

LibraryID：资料库文件夹。用户添加的根目录之间有包含关系时归为一组，只有最外层的根目录是资料库，组内其它根目录的视频与字幕归它所有。
VideoID：视频文件（例如1.mkv），观看状态和进度属于它。
SubtitleID：字幕文件（例如1.ass）。
CueID：对于SRT字幕而言是一条字幕的ID，对于ASS字幕而言是一条Event的ID。注意此处与CueGroup区分开来。
ExcerptID：收藏记录。

## 补充说明
1. 资料库、视频和字幕都以当前绝对路径为身份；视频和字幕另存相对于资料库的路径。
2. 观看状态、播放进度、播放历史、默认音频源、默认字幕引用 `VideoID`。字幕事件引用 `SubtitleID`。Excerpt 引用 `CueID`。标签引用 `ExcerptID`。字幕与视频的匹配关系保存 `SubtitleID + VideoID`。
3. `VideoID` 和 `SubtitleID` 是一对多的关系。
4. App 内改名只改路径，保持全部 ID；观看状态、播放进度、播放历史、默认音频源、默认字幕、Excerpt 与封面随之保留，改名后无需 Index。
5. 默认音频源记录第几条音轨，未设置时为第 1 条，Index 不修改它。播放与 Anki 导出时，文件中没有该音轨则使用第 1 条。
6. 一个视频的字幕顺序：去掉最后 1 级后缀名后，与去掉最后 1 级后缀名的视频名称完全一样的排在最前，有多条时 ass 在 srt 之前；其余按文件名排序，不区分大小写，数字按数值比较。默认字幕记录某一条字幕，未设置或该字幕不再匹配该视频时为第一条，Index 不修改它。
7. Index、Add Folder、Remove Folder 与 App 内改名只在正在播放的视频被移出库时停止播放，其余情况不影响播放。
8. 视频或字幕文件在 App 之外被改名、移走或无法读取时，数据库不变。各入口照常可以进入，由播放页按加载失败处理；只有需要文件内容的环节才读取文件。
