# 1. 视频与字幕匹配规则流程
1. 找到同一文件夹下（不包含子文件夹）的所有字幕。
2. 每个字幕，最多只能匹配同一文件夹下（不包含子文件夹）的一个视频文件。
3. 去掉字幕文件的最后1个扩展名，尝试匹配所有去掉最后1个扩展名的完全匹配的视频。如果能，进入第8步；不能，进入第4步。
4. 去掉字幕文件的最后1个扩展名，尝试匹配所有到去掉最后2个扩展名的完全匹配的视频。如果能，进入第8步；不能，进入第5步。
5. 如果字幕文件不存在2个扩展名，匹配失败；如果字幕文件存在2个扩展名，进入第6步。
6. 去掉字幕文件的最后2个扩展名，尝试匹配所有到去掉最后1个扩展名的完全匹配的视频。如果能，进入第8步；不能，进入第7步。
7. 去掉字幕文件的最后2个扩展名，尝试匹配所有到去掉最后2个扩展名的完全匹配的视频。如果能，进入第8步；不能，匹配失败。
8. 这一步处理匹配到的视频文件的优先级。此时只存在后缀名不同的情况，暂定为：.mkv > .mp4 > .webm > .flv > .avi > .mov。

例如：

```text
E01.mkv
E01.ass ✅
E01.SC.ass ✅ 允许多一个后缀层级
E01.SC.v2.ass ❌
Other.ass ❌
```

```text
E01.SC.mkv
E01.ass ✅ 允许少一个后缀层级
E01.SC.ass ✅ 
E01.TC.ass ✅ 允许换一个二级后缀名
E01.SC.v2.ass ❌
Other.ass ❌
```

匹配时处理扩展名大小写和 Unicode 规范化，保证 macOS、Windows 行为一致。

# 2. 永久身份与路径分离

数据库中的主要对象都有自己的永久 ID：

```text
LibraryID
 ├── VideoID
 ├── SubtitleID
 │    └── CueID
 │          └── ShioriID
```

LibraryID：用户添加的资料库文件夹。
VideoID：视频文件（例如1.mkv），观看状态和进度属于它。
SubtitleID：字幕文件（例如1.ass）。
CueID：该字幕文件中某一句 Cue/Event。
ShioriID：收藏记录。
