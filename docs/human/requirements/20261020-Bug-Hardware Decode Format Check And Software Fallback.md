# 需求描述

1. **打开视频时精准识别硬件不支持的画面规格并自动回退软解**：
   - 在硬件优先模式（`Hardware` / `Auto`）下打开视频时，除检测视频编码大类与芯片代际能力（如 M1 / M2 不支持 AV1 硬解、M3 及之后芯片支持 AV1 硬解）外，还需结合视频的具体色深与色彩采样规格判断是否支持苹果硬件解码：
     - 所有超过 10-bit 色深的视频（如 **HEVC 12-bit**、**VP9 12-bit**、**AV1 12-bit**、**H.264 12-bit** 等）；
     - **VP9** 与 **AV1**（在支持 AV1 硬解的 M3 及之后芯片上）的非 4:2:0 色彩采样视频（如 **4:2:2**、**4:4:4**、**RGB** 或单通道格式）；
     - **H.264** 的非 8-bit 4:2:0 硬件不支持规格（如 **10-bit**、**4:2:2 / 4:4:4**、**RGB** 等）。
   - 凡命中上述硬件不支持规格的视频，在打开阶段即自动回退为软件解码，并在播放诊断日志中记录具体回退原因。

2. **首帧解码与画面上屏阶段的软解兜底接管**：
   - 若视频在打开阶段进入硬解通道，但在实际解出画面帧时系统内部降级为软件画面，或硬解在首帧阶段报错拒收，播放器必须自动切换并接管至软解渲染通道（包含对需要独立软解器的编码自动重开为软解），严禁因硬解状态锁死而丢弃画面帧，杜绝“有声音、画面黑屏、进度条无法拖动”的现象。

# 验收标准

1. 在 M1 / M2 与 M3 / M4 及之后芯片设备上，以 `Hardware` 或 `Auto` 模式播放 **HEVC 12-bit**、**VP9 12-bit**、**VP9 4:2:2 / 4:4:4** 等视频时，均能自动回退至软件解码，画面显示、声音播放与进度条拖拽全部正常，日志明确记录回退原因。
2. 在 M3 / M4 及之后芯片设备上，常规 **AV1 8-bit / 10-bit (4:2:0)** 视频正常使用硬件解码；播放 **AV1 12-bit** 或 **AV1 4:2:2 / 4:4:4** 视频时自动回退至软件解码正常播放，无黑屏或进度条卡死。
3. 若遇到打开阶段放行但在读取首帧时才退回软件画面的特殊视频，播放器能直接将软件画面正常渲染上屏并解锁时间轴，不出现黑屏丢帧。
