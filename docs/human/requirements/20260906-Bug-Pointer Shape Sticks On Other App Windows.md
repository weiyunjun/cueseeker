# 缺陷描述

## 1. 复现与现象

1. 打开设置界面，使其与主窗口同时可见。
2. 把指针移到主窗口表格的字幕文本上，指针变为 Grab。
3. 沿途不离开会显示 Grab 的区域，把指针移入设置窗口。

指针在设置窗口上保持 Grab，并且在设置窗口内任意移动都不恢复。设置窗口没有任何区域应显示 Grab。

## 2. 期望

1. 指针规则只在主窗口内生效。
2. 指针离开主窗口时恢复默认样式。
3. 主窗口之外的窗口（设置窗口等），指针形状由系统决定，App 不设置也不改写。
4. 指针从其他窗口回到主窗口后，按现有规则在下一次真实移动时重新判定。

## 3. 实现约束

1. 生效范围按指针实际所在的窗口判定，不用坐标是否落在主窗口范围内推断。
2. 不为设置窗口单独实现指针逻辑，也不把设置窗口纳入界面层级表。
3. 不新增状态来源，沿用现有形状持有者。

## 4. 不在本单范围内

1. 主窗口内 Grab 与 I-beam 的判定清单不变。
2. 界面切换、菜单/Dialog、Grab 目标失去 hover 三类复位事件不变。
3. 播放页无操作后隐藏指针的行为不变。

## 5. 设计文档

验收通过后，在 `docs/human/design/UI Application Rules.md`「指针」章节补入以下条款：

- App 的指针规则只在主窗口内生效。指针离开主窗口即恢复默认样式；主窗口之外的窗口，指针形状由系统决定。

# 验收

1. 设置界面打开时，指针在表格字幕文本上为 Grab，移入设置窗口后为箭头。
2. 指针在设置窗口内移动，形状与系统一致：可输入区域为 I-beam，其余为箭头。
3. 指针从设置窗口移回表格字幕文本上，重新为 Grab。
4. 指针移出 App 所有窗口再移回主窗口空白区域，为箭头。
5. `20260902-UI-Pointer Shape Follows Pointer Movement.md` 规则解释 4 的 7 个场景全部不变。
6. 现有自动化端到端与单元用例全部通过。
7. 指针形状由需求方人工验收。
