# 需求描述

## 1. 播放触发诊断日志
1. **播放行为日志**：每次触发视频播放（打开新视频或切换播放条目）时，必须输出结构化日志。
2. **日志字段要求**：明确包含：
   - 视频文件路径与视频编码（Codec：如 AV1、H.264、HEVC）。
   - 用户配置的解码模式（Decoder Setting：Hardware / Auto / Software）。
   - 实际生效的解码方式与内核（如 `Hardware (VideoToolbox)` 或 `Software (libdav1d)`）。
   - 是否触发自动回退及回退原因（例如当前硬件不支持该编码硬解）。

## 2. 解码器选项行为对齐与即时更新
1. **选项语义**：
   - `Hardware` 与 `Auto`：统一为“默认优先硬件解码，在硬件不支持或硬解异常时自动回退为软解”。
   - `Software`：强制使用 CPU 软件解码。
2. **设置即时生效**：在设置中切换解码器模式后，无需重启应用，下一次触发播放或跳转到下一个结果时必须即时应用新设置。

## 3. 两道闸门硬件能力检测与软解回退
1. **第一道闸门（索引与元数据预路由）**：结合库中已索引的视频编码信息与当前设备硬件能力，对于已知不支持硬解的格式（如 M1 芯片播放 AV1），快速决定初始路由。
2. **第二道闸门（底层运行时毫秒级检测与回退）**：底层播放内核在准备硬件解码前快速检测硬件是否真正支持该编码（如调用 VideoToolbox 能力检测）；若硬件不支持或硬解异常，自动无缝回退至软解（如 AV1 回退至 `libdav1d`），确保视频正常播放，杜绝黑屏与卡死。

# 验收标准

1. 每次触发播放时均能看到包含编码、配置模式与最终生效解码器的日志。
2. 在 M4 设备上，切换为 `Software` 时日志显示使用软解（如 `libdav1d`），切换为 `Hardware`/`Auto` 时显示使用硬解，且在切换后播放下一条目时即时更新生效。
3. 在不支持 AV1 硬解的设备（如 M1）上，播放 AV1 视频时自动触发向软解的回退，视频正常渲染播放，无黑屏卡死，日志明确记录回退原因。
