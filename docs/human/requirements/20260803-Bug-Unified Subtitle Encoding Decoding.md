# 需求描述
1. 现状：同一字幕文件在索引和播放阶段使用不同的字符编码处理路径，可能出现可以正常索引、但播放或截图无法加载的问题。
2. 目标：ASS 和 SRT 必须使用唯一、统一的字幕解码规则，索引、播放及字幕截图对同一源文件必须得到一致文本。
3. 解码顺序：
   - 优先识别 UTF-8、UTF-16 LE/BE 等 BOM。
   - 无 BOM 时先严格验证 UTF-8。
   - 非 UTF-8 时使用可靠的字符集探测，支持常见的 Shift-JIS/CP932、EUC-JP、GB18030/GBK 和 Big5 字幕。
   - 解码结果必须通过对应 ASS 或 SRT 基本结构验证。
4. 解码后的字幕统一转换为 UTF-8，再交给字幕解析器和 libass；不得让 libass直接猜测未知编码。
5. 不得修改源字幕文件，不得因编码统一引入数据库副本、额外缓存或重复解析规则。
6. 无法可靠解码时必须明确报告失败，不得静默生成乱码索引或乱码字幕。
7. 本需求不新增手动选择字幕编码的设置界面；如自动探测仍存在真实无法判断的文件，另立需求处理人工覆盖。

# 验收标准
1. 指定的 UTF-16LE ASS 文件无需转码即可正常索引、播放和截图。
2. UTF-8、UTF-16LE、UTF-16BE 及常见无 BOM 东亚编码测试文件均可正确处理。
3. 同一测试字幕在索引与播放路径得到一致的文本和 Cue。
4. 非法或无法识别的字幕必须失败并给出诊断，不得显示乱码。
5. 现有 ASS 样式、字体、分段缓存及 SRT 排版行为不得回归。
