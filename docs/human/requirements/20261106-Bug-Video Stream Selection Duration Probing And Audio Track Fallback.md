# 需求描述

1. **播放器主视频轨选择排除内封静态封面附图流（本地与远程）**：
   - 当视频容器（如 MKV、MP4 等）内同时包含正片视频流与作为封面海报嵌入的静态图像流（携带附图标记的 MJPEG / PNG 流），且该静态封面流在容器轨道表中排在第 0 号轨道（位于正片视频流之前）时：
     - 播放器打开视频时必须与元数据探测、Library 封面生成及关键帧预览缩略图保持统一的选轨策略，自动排除所有携带静态附图标记的封面轨道，优先选择主正片视频流进行解码渲染与进度跳转（Seek）；
     - 严禁仅按容器内轨道序号顺序盲目选取第 0 条视频类型轨道，避免将 1 帧静态海报流当作正片视频轨打开，从而导致播放页画面停留在竖版静态海报、总解码帧数仅有 1 帧、播放时间卡在 `00:00` 且拖拽进度条无法跳转画面；
     - 仅当容器内所有视频流均为静态附图流而不存在任何正片视频流时，才回退选取首条视频流。

2. **容器头与流头均未写入总时长时的尾部时间戳时长兜底探测（本地与远程）**：
   - 当视频文件（如未在文件头写入总时长的 MKV 流式转封装文件、缺失头部时长的节目流或传输流）经过常规头部与流信息探测后，容器级总时长与各条音视频流时长均为未知或 `0` 时：
     - **元数据探测与入库时长兜底**：在元数据探测阶段自动通过定位至文件尾部区域读取末尾有效音视频数据包的时间戳，结合容器起始时间偏移计算出真实总时长，并基于文件物理字节大小与真实总时长反推计算出容器平均总码率（`文件字节大小 × 8 / 真实总时长`）；
     - **Library 剧集封面与时长角标恢复**：消除因头部探测时长为 `0` 而直接跳过 Library 剧集自动封面生成的缺陷，确保此类无头部时长视频在添加文件夹或重新索引后，能按兜底探测出的真实总时长采样截取画面生成剧集封面，并在 Library 与 Recent 卡片上正常显示时长角标；
     - **File 页面「文件详情」展示**：在 `L-06.8 File Detail Dialog Layout` 弹窗中准确展示兜底探测出的「时长（Duration）」与计算所得的「码率（Bitrate）」，不再因文件头缺失时长字段而显示为空占位符 `-`；
     - **播放器进度条总时长兜底**：播放器打开此类视频时同步采用尾部时间戳兜底探测出的真实总时长，确保播放页底部进度条右侧总时长正常展示，且进度条拖拽跳转、悬停预览缩略图与播放结束判定均按真实总时长正常工作。

3. **无效空白幽灵音轨过滤与损坏/不支持音轨的自动顺延回退（本地与远程）**：
   - **过滤声道数或采样率为 0 的无效空白音轨**：
     - 针对广播电视录制流（如 MPEG-TS `.ts`）或多路复用容器中常出现的未激活空白占位音频流（表现为声道数 `<= 0` 或采样率 `<= 0`）：
     - 在元数据探测入库、File 页面「文件详情」弹窗的 `Audio #N` 分组以及播放页 `More -> Audio Track` 音轨切换菜单中，统一过滤剔除所有声道数 `<= 0` 或采样率 `<= 0` 的无效空白音频流，仅将具备有效声道数与有效采样率的真实可用音轨按顺序编号展示并纳入音轨切换索引。
   - **播放器打开音轨失败时的自动顺延回退与静音降级**：
     - 当播放器在打开视频并初始化默认或指定音轨（如第 1 条音轨）时，若该音轨因流参数损坏（如声道数为 0、采样率无效）、缺少对应音频解码器（如未内置解码器的专有语音编码）或音频输出引擎创建失败而无法就绪：
       1. 播放器严禁直接中止整个视频文件的打开流程而导致视频黑屏报错；
       2. 播放器须在容器其余有效音频流中按顺序自动尝试回退打开下一条可正常解码输出的音轨，并将当前激活音轨索引同步更新为实际成功打开的音轨；
       3. 若容器内所有音频流均无法解码或初始化失败，则自动关闭音频输出通道，安全降级为依靠视频时钟驱动的纯画面无声播放，确保视频画面照常解码渲染、倍速与跳转（Seek）均不受影响。

4. **File 页面「文件详情」与播放页音轨菜单补齐 4 类传统视音频编码可读名称**：
   - 在现有视音频编码可读名称映射基础上，补齐以下 4 类遗漏传统编码的标准展示名称，消除直接将底层原始编码代号转大写展示的情况：
     - 视频编码：`h263` / `h263p` / `h263i` 统一展示为 `H.263`；`flv1` 统一展示为 `Sorenson Spark (FLV1)`（或 `FLV1` 标准可读名）。
     - 音频编码：`cook` 统一展示为 `RealAudio Cook`；`speex` 统一展示为 `Speex`。

# 验收标准

1. **前置内封封面视频正常播放正片**：打开第 0 号轨道为内封静态海报（`600×800` MJPEG）、第 1 号轨道为 `1920×1080` H.264 正片的 MKV 视频时，播放器准确选中 `1920×1080` 正片视频流进行硬件解码播放，进度条拖拽跳转、缩略图预览、台词拼图与 Anki 导出均输出正片画面，不再停留在静态海报。
2. **无头部时长视频全链路时长、封面与进度条正常**：对文件头与流头均无时长信息的 MKV 视频执行索引、查看详情与播放时，Library 剧集卡片正常生成剧集封面并显示真实时长角标（如 `02:00`），File 页面「文件详情」准确展示时长与总码率（不再显示 `-`），播放页底部进度条显示真实总时长并可任意拖拽跳转。
3. **空白幽灵音轨过滤与损坏音轨自动回退生效**：
   - 查看含 `0 声道 / 0Hz` 空白音频流的 `.ts` 视频「文件详情」与播放页 `Audio Track` 菜单时，仅列出真实有效音轨，不再出现声道或采样率为 0 的幽灵音轨；
   - 打开首条音轨为 `0 声道 / 0Hz` 损坏流、第 2 条音轨为正常双声道音频的 `.ts` 视频时，播放器自动跳过损坏首轨并切换至第 2 条正常音轨流畅播放音画；打开仅含不支持音频编码（如 `speex`）的视频时，播放器自动降级为无声画面播放，不报错黑屏。
4. **传统编码名称可读化展示**：查看含 `h263`、`flv1`、`cook`、`speex` 编码的视频「文件详情」与播放页音轨菜单时，均准确展示为规范可读名称。
