# 需求描述

1. **非零起始时间戳视频在台词拼图（Collage）中的时间轴基准对齐（本地与远程）**：
   - 当媒体容器（如带起始偏移的 MKV、`.ts`、`.m2ts` 等）的音视频流起始时间戳不为 0（例如音视频流从 `10.0s` 起步，而内封或外挂字幕时间轴从 `0.0s` 起步）时，播放器、进度条预览缩略图与 Anki 导出均以容器最早有效起始时间戳作为相对时间轴零点（`00:00`）：
     - 修复「台词拼图（Collage）」提取视频画面时，因对 MKV / WebM 容器跳过流信息探测而未能读取到容器非零起始时间偏移、导致截帧定位时间未加上容器起始偏移的缺陷；
     - 在 Collage 抽帧时确保准确计入视频容器的真实起始时间偏移，使每条字幕的相对时间点精准对应到与播放器相同的视频帧，彻底消除截出的每一张台词画面均比播放器实际画面整段偏早（偏早时长等于容器起始偏移量）的图文错位问题；
     - 确保同一字幕时间点在播放页画面、进度条预览缩略图、播放器单帧截图、台词拼图（Collage）与 Export to Anki 中的视频画面严格一致。

2. **播放中途时间戳正向跳变与归零回绕的动态时钟校准（本地与远程）**：
   - 针对 MPEG-TS（`.ts` / `.m2ts`）拼接广播流或 DVD VOB（`.vob` / `.mpg`）多章节交界处常见的流内时间戳不连续现象（即播放中途音视频帧时间戳突然大幅正向跳变数百秒，或突然归零回绕至 `0` 附近），在播放器连续解码循环中建立流内时间戳连续性检测与动态偏移校准机制：
     - **中途时间戳大幅正向跳变校准**：当连续读取解码的音视频数据包/帧时间戳相比上一帧正常递增位置发生超出合理阈值的突增（如从 `10.0s` 突增至 `610.0s`）时，自动检测该跳变点并扣除跳变差值以修正后续帧的逻辑播放时间，同时重锚定音画同步时钟，严禁视频帧限速逻辑因看到突增后的未来时间戳而原地休眠等待数百秒导致画面彻底冻结，并确保直接拖拽跳转（Seek）至跳变点之后的位置也能正常出画；
     - **中途时间戳归零回绕校准**：当连续读取解码的音视频数据包/帧时间戳相比上一帧位置发生大幅倒退（如在 DVD VOB 章节交界处从 `36.45s` 归零回绕至 `0.28s`）时，自动将回绕前的累计播放时长叠加为后续帧的逻辑时间偏移，确保：
       1. 播放进度条当前时间跨过交界点时保持单调平滑递增（如从 `00:36` 平滑递增至 `00:37`），严禁进度条瞬间倒退跳回 `00:00`；
       2. 回绕后的视频帧目标呈现时间与音频时钟保持同步限速，严禁因时间戳归零变小导致目标呈现时间小于当前系统时钟而失去限速控制、出现画面以快进残影狂飙的现象；
       3. 当用户先跳转（Seek）至回绕点之前的某个非零时间点（如 `00:30`）再继续播放跨过回绕点（`00:36`）时，经偏移校准后的后续帧逻辑时间均大于跳转目标时间（`30.0s`），严禁被跳转前帧过滤逻辑误判为“早于跳转目标 `30.0s`”而把回绕后的音视频帧整段静默丢弃导致黑屏无声。

3. **蓝光 `.m2ts` / 广播 `.ts` 流非关键帧首包硬件解码保活与音早于画首帧快速上屏**：
   - **非关键帧首包不误触发硬件解码永久降级**：
     - 在打开或拖动跳转（Seek）`.m2ts`、`.ts` 等流式封装视频时，容器定位到的起始读取位置常位于首个 IDR 关键帧之前的非关键帧（B 帧 / P 帧）或缺少参数集的前导包处。此时 Apple VideoToolbox 硬件解码器对前几个非关键帧数据包返回解码错误属于正常的流同步过程。
     - 修复当前「只要首个视频包送入解码器返回错误就立即销毁硬件解码上下文并永久切换为软件解码」的过激回退逻辑：在刚打开或刚跳转尚未解码出首帧期间，优先跳过首个关键帧之前的非关键帧数据包；即便首个关键帧之前的过渡包触发硬件解码器报错，也应继续读取并送入后续关键帧尝试硬件解码，仅当送入有效关键帧后硬件解码器依然无法解码出画面时，才执行软件解码回退，确保蓝光原盘 `.m2ts` 与广播 `.ts` 稳定保持硬件加速解码。
   - **流内音频起点早于首个视频关键帧时的首帧快速呈现**：
     - 当广播流（如 `.ts`）内音频流起始时间戳比首个可解码视频关键帧早 1 秒以上（如音频从 `0.0s` 起步，而首个视频关键帧在 `1.12s`）时，打开视频后解码器应快速跳过前导无关键帧区间解码出首个视频关键帧并立即上屏展示，消除刚打开视频前 1 秒以上黑屏无画面的等待延迟。

4. **RMVB（`rv40` / `rv30`）分片关键帧在进度条预览缩略图中的完整拼装解码**：
   - 修复播放进度条关键帧预览缩略图解码器在读取 `.rmvb` 视频时始终返回空图像的缺陷：
     - RMVB 容器将一个完整的关键帧画面拆分为多个连续的数据包分片，当首个分片包送入解码器后，解码器尚未凑齐整帧数据而不会立即输出画面；
     - 缩略图解码器严禁在送入第 1 个带关键帧标记的分片包且尚未收到输出帧时，就立即向解码器发送空包冲刷并清空解码器内部缓冲区（此举会直接销毁正在拼装中的半截关键帧）；
     - 必须在连续读取并送入后续分片数据包直至解码器成功拼装输出首帧完整画面（或达到最大探测包数上限后）再执行冲刷收尾，确保悬停或拖拽 `.rmvb` 进度条时正常弹出预览缩略图。

# 验收标准

1. **非零起点视频台词拼图（Collage）画面精准对齐**：对音视频从 `10.0s` 起步、内封字幕从 `0.0s` 起步的 MKV 视频执行 Collage 台词截图预览、复制与导出时，每一句台词截出的视频画面均与播放页在该台词时间点显示的画面及 Anki 导出配图完全一致，不再出现整体偏早 10 秒的画面错位。
2. **中途时间戳正向跳变与归零回绕视频连续平稳播放**：
   - 播放第 `10.0s` 处时间戳正向跳变 600 秒至 `610.0s` 的 `.ts` 视频时，跨过 `00:10` 交界点画面与声音无缝衔接继续播放，不再冻结卡死在第 `10.03s`；拖动进度条至 `00:10` 之后也能正常出画播放；
   - 从头或从 `00:30` 跳转后播放第 `36.45s` 处时间戳归零回绕至 `0.28s` 的 DVD `.VOB` 视频时，跨过 `00:36` 交界点后进度条继续向 `00:37`、`00:38` 单调递增，画面按正常帧率平稳播放且声音连续，不再发生进度条倒退回 `00:00`、画面快进狂飙或黑屏丢帧。
3. **蓝光 `.m2ts` / 广播 `.ts` 保持硬件解码且首帧立即上屏**：打开或拖动跳转 H.264 蓝光 `.m2ts` 与广播 `.ts` 视频（含带局部坏包或非 IDR 起始包的流）时，播放器稳定保持 VideoToolbox 硬件加速解码，不再被误降级为软件解码；且当音频起点早于首个视频关键帧约 1 秒时，打开视频后首帧画面立即呈现，无前导黑屏。
4. **RMVB 进度条预览缩略图正常展示**：在播放页打开 `.rmvb`（`rv40`）视频并悬停或拖拽底部进度条时，进度条上方正常实时显示对应时间点的关键帧预览缩略图。
