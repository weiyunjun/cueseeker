# 背景

搜索「の」当前首屏需要约 0.8–1.8 秒，全量结果需要 6 秒以上；7 月中旬首屏为 3 毫秒。原因是 7 月 25 日增量索引提交后，FTS 行序不再等于展示顺序，搜索改为对全部命中排序后才返回首屏，且精确计数按批重复排序，进度更新重复发布全部结果。筛选条件不参与搜索，先出未筛选首屏、精确完成后再替换，属于错误决策，本需求一并纠正。

# 需求描述

## 1. 排序规则

1. Search 表格按 Display Title、字幕路径、Cue 时间的顺序排列；首屏、后续加载页与精确完成后的顺序一致。
2. 该规则写入 `UI Design System.md` 的 Search / Excerpt Table Layout 的 Ordering 条目。

## 2. 首屏

1. 首屏只读取产生前 100 条所需的候选，不为返回首屏而读取或排序全部命中；无论索引以何种顺序写入，顺序遵守规则 1。
2. 首屏显示的就是筛选后的结果，不再显示未筛选结果，也不因后续计算而替换内容。

## 3. 筛选先行

1. Filter Menu 的勾选条件进入搜索本身，首屏与其余结果均按当前勾选得到。
2. 精确总数与有序结果单趟扫描得到，不重复读取或排序已扫过的候选；进度更新只发布新增部分，不重复发布已发布的结果。

## 4. 未勾选项计数

1. 筛选结果完成后，再计算未勾选项的计数。计数语义不变：每张卡片的计数忽略本卡片的勾选，叠加其他三张卡片。
2. 计算期间对应计数显示 calculating。
3. 计算期间修改搜索词或勾选时直接开始新的搜索或计算，旧结果不得发布。

## 5. 基线与验证

1. 改动前先在当前版本记录基线；每一步改动后用同样方式测量并与基线对比，目标指标回退即停止。
2. 基线查询词：`の`（大量）、`今`（中量）、`大丈夫`（少量）。
3. 测量项：首屏耗时、筛选结果完成耗时、未勾选项计数完成耗时、主线程与界面耗时。
4. E2E 通过剪贴板粘贴输入查询词。

## 6. 不做

1. 不改 FTS 分词与匹配规则。
2. 不改结果数量与计数语义。
3. 不新增前端性能显示。
