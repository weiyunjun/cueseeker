# 需求描述

1. **筛选与排序属性前置确定原则**：
   - 所有参与筛选（Filter）与排序（Sort）的属性，均须在搜索或列表展示前确定并持久化就绪（入库即可确定的属性在 Index 阶段写入，用户交互产生的属性在操作发生时写入）。
   - 搜索、统计 Filter 各筛选项数量分布、以及执行排序时，直接读取已确定的属性值，不在搜索或排序过程中对台词文本进行临时解析与计算。

2. **台词「时长」与「字符数」在 Index 阶段预存**：
   - 在 Index 入库阶段预先计算并持久化每条台词的**时长**与**字符数**（失效摘录同步保留），供全库筛选统计、Search 搜索筛选与排序、Excerpt List 筛选与排序直接读取。
   - 旧数据库在应用启动升级时自动补齐已有台词的时长与字符数，无需用户手动重新 Index。

3. **搜索性能基准测试（Benchmark）**：
   - 修改代码前，在与上次基准测试相同的数据库上搜索日语 `の` 并记录各项耗时基线；改动完成后再次执行对比，验证去掉临时计算后的搜索性能表现。

# 验收标准

1. Search 与 Excerpt List 的筛选区间统计（时长、字符数等）与排序（字符数最多、字符数最少等）结果准确，搜索与排序全流程直接读取预存属性，不再临时计算字符数或时长。
2. 已有数据库平滑升级后无需重新 Index，筛选统计与排序表现正常。
3. 修改后搜索日语 `の` 的 Benchmark 耗时相比修改前无退化且有所优化。
