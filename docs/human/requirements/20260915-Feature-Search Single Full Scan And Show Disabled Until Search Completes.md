# 背景

有勾选时，搜索先单独读取首屏，再按勾选扫描得到结果，最后再扫描一趟得到未勾选项的计数。数据量大时总时长明显增加，且没有实质性的好处。

# 需求描述

## 1. 基线

1. 改代码前在当前版本记录基线，查询词 `の`：
   1. 无勾选：首屏耗时、全量完成耗时。
   2. 只勾选 Character `11–20`：首屏耗时、筛选结果完成耗时、全部计数完成耗时。
2. 每一步改动后用同样方式测量并与基线对比。目标指标为完成耗时，回退即停止；首屏耗时一并对比，明显变慢时停止并报告。

## 2. 第一步：一趟全量扫描

1. 一次搜索只扫描一趟，读取查询的全部命中，按当前勾选筛选得到表格结果，同时得出全部计数。不再单独读取首屏，也不再为计数另扫一趟。
2. 表格只接收两次推送：筛选后的结果达到 100 行时推送前 100 行，扫描完成后推送其余全部行；扫描完成时不足 100 行，只推送一次全部结果。
3. 扫描完成时，总数与全部计数同时出现。
4. 对话框只在搜索开始与搜索完成两个时刻更新；对话框内改勾选时照常立即更新。
5. 排序、结果数量与计数语义不变。

## 3. 第二步：Show 等待总数

1. Filter 对话框中总数未知时，Show 为 Disabled，回车同样不生效；总数出现后恢复。
2. 胶囊照常可以勾选与取消，Reset、Cancel 与 Esc 不受影响。

# 验收

1. 第 1 节基线已记录；第一步完成后，`の` 无勾选的全量完成耗时不慢于基线，只勾选 `11–20` 的全部计数完成耗时低于基线，首屏耗时按第 1 节第 2 条对比。
2. `の` 只勾选 `11–20`：首屏只含该条件的行，之后不被替换；扫描完成后表格行数等于总数，总数与全部计数同时出现。
3. 扫描完成后改勾选并点击 Show，不重新搜索，表格行数等于总数。
4. 第二步完成后：搜索期间打开对话框，Show 为 Disabled、回车无效、胶囊可切换；搜索完成后 Show 显示总数并可点击。
5. 现有自动化端到端与单元用例全部通过；不为本需求新增 E2E 能力。
