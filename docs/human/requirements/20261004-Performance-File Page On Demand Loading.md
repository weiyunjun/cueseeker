# 需求描述

## 1. 移除无关加载与任务干扰

1. File 界面展现或停留期间，不触发 Library 媒体库的封面渲染或合集摘要计算，避免无关后台任务占用资源。
2. File 界面的数据加载保持独立，不受媒体库其他业务（如封面生成、播放历史变化）刷新信号的干扰或重置。

## 2. 1~3 级界面极简直查与零延迟呈现

1. **坚持纯按需直查（不预占内存）**：坚决不对未打开的目录进行预加载，不把其他文件夹数据强塞进内存缓存，避免增加内存常驻。
2. **一级界面（Roots 根目录）**：仅直接查询已添加的根目录列表，彻底废弃全库媒体树（`contentTree`）的全量扫描与关联，进入即呈现。
3. **二级界面（Subfolders 子目录）**：下钻时仅针对当前根目录单次精准直查子文件夹列表，废弃重型通用展示树与前缀大范围扫描，首帧直接呈现。
4. **三级界面（Files 文件流）**：下钻时仅针对当前文件夹单次精准直查音视频与字幕文件及大小，废弃多表临时重排与多轮 N+1 拆分查询，首帧直接呈现。
5. **消灭无意义的 Spinner 占位**：本地数据库单次极简直查均在微秒级完成，各级页面下钻时直接渲染内容列表，彻底消除转菊花等待与闪烁。
6. 保持现有重命名、删除、空状态及面包屑导航等既有交互功能完整可用。

# 验收

1. **1~3 级即时呈现**：进入根目录、二级子目录、三级文件流时，卡片列表均首帧直出秒开，彻底无体感加载等待与转菊花。
2. **纯按需与低开销**：下钻过程无后台多余预加载任务，未访问的文件夹不占用内存。
3. **文件数据准确**：三级文件流音视频及关联字幕完整展示，文件大小与名称显示正确。
4. **操作完备性**：各级界面的重命名、删除操作，以及前进/后退历史导航与面包屑跳转均正常可用。
5. **测试要求**：
   - 视觉与端到端流畅度由所有者人工验收。
   - 1~3 级单点直查逻辑与路由流转由自动化测试覆盖且全部通过。
