# 需求描述

## 问题

索引的执行顺序是先读数据库当前状态，再花较长时间扫描与解析，最后一次性写回，
中间过程不在事务内。两个 App 实例同时索引同一个数据库时，后写入的一方使用的是
过期快照，可能覆盖较新的结果，并使 Shiori 引用的 Cue 既不在有效 Cue 也不在
Tombstone 中。

## 规则

1. 同一时间只允许一个 CueSeeker 实例运行。
2. 启动时发现已有实例正在运行的，激活已有实例的窗口后退出，不得静默退出。
3. 同一实例内，索引进行期间不得启动新的索引。触发时直接拒绝，不取消正在运行的索引。
4. 不使用数据库持久令牌保护索引发布权。

# 验收标准

1. 已有实例运行时再次启动 App，最终只保留一个实例，且已有窗口被激活。
2. 索引进行期间触发索引，操作被拒绝，正在运行的索引不受影响。
3. 数据库中不再保留索引发布令牌。

# 验证方式

单实例行为由人工验证一次并记入实现记录，本次不新增自动化端到端能力。
