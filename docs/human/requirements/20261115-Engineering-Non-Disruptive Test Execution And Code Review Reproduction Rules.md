# 需求描述

1. **自动化测试静默无窗口执行规范（保留既有测试文件不变）**：
   - 开发与修改过程中检查代码正确性时优先仅运行编译验证；执行自动化测试（以及在跨对话指令中编写测试要求）时，必须仅定向运行相关的无窗口纯逻辑测试或显式跳过会创建可见窗口、抢占桌面焦点的历史界面测试套件。
   - 未经明确要求，禁止默认执行无过滤的全量测试命令，避免测试过程反复弹出客户端窗口闪烁屏幕、打断用户正常桌面操作。

2. **代码审查（Code Review）复现步骤先行与入口核实规范**：
   - **报出前强制核实真实入口与设计规则**：审查代码报出疑似问题前，必须先在源码中核对真实的界面文案、菜单项与快捷键定义，并对照相关产品与交互设计文档确认该行为并非既有设计规定；对于常规界面操作无法触发的纯理论分支，不得编造操作路径或将其作为常规问题上报。
   - **默认给出具体复现步骤并等待人工实测确认**：审查输出须默认包含清晰的问题现象、精确到具体界面与操作动作的复现步骤、以及预期与实际表现对比；在人工实测确认问题真实存在之前，严禁擅自修改代码或直接生成修复执行指令。
   - **确认复现后先对齐根因与修复方案**：人工确认问题复现后，须先说明修改前为何正常、本次改动引入异常的原因及预计修复方案，待方案达成一致并获明确要求后再输出修复指令或执行修改。

# 验收标准

1. **工程规范一致无冲突**：工程协作规范与测试规范文档已同步补充静默测试执行要求与代码审查复现核实要求，并修正此前可能诱导无过滤运行全量窗口测试的表述。
2. **存量代码与测试零改动**：本次仅更新工程规范文档，不改动业务源码与任何既有测试文件。
