# 需求描述

1. **自动化测试纯逻辑定界与零测试后门污染**：
   - 自动化测试严格限定于纯数据计算、字幕解析、搜索匹配、数据库读写与迁移、以及脱离界面的纯数据业务规则，仅覆盖核心路径与关键边界，禁止按需求列举的界面入口做排列组合堆砌。
   - 凡涉及窗口、鼠标悬停、光标样式、菜单与弹层、文字视觉排版居中、以及视频与字幕首帧画面呈现的改动，默认通过编译检查、既有测试套件零退步与人工端到端验收验证；移除工程文档中“凡修问题必先写自动化复现测试”及“界面与播放回归尽量补充自动化模拟检查”的旧要求，未经明确要求不新增界面或播放模拟测试。
   - 严禁在单元测试中构造假窗口、假视图层级或伪造鼠标键盘事件模拟界面交互；严禁为配合测试在正式业务代码中添加专供测试使用的属性、人工延迟开关、重置入口或计数探针。

2. **最小充分设计与统一规则的代码边界澄清**：
   - 明确“禁止硬编码与私自特殊实现”约束的是产品与交互规则遵循统一设计规范、不引入脱离文档的特例，而非要求在代码结构上封装重型通用框架。
   - 多处界面遵循同一设计规则时，优先原位修改或复用设计常量与极简共享函数；未经明确批准，禁止平地新建独立通用引擎、管理层或冗余中间数据模型。

3. **方案对齐规模预估与验收返工减法原则**：
   - 方案讨论对齐阶段须同步说明预计修改的现有位置、大致改动规模及是否需要新增独立抽象，在动工前拦截过度设计。
   - 验收迭代出现异常时，须先审视上一版实现是否绕远或引入多余状态，优先通过删减冗余分支和回退过度包装解决问题，严禁在复杂逻辑上叠加状态开关打补丁。
