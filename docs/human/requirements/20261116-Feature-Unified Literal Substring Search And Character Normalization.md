# 需求描述

1. **统一字符归一化规则（不修改原始展示文本）**
   - 搜索索引与搜索匹配两端采用完全一致的字符归一化处理：
     1. **Unicode `NFKC` 兼容归一化与小写转换**：打通全半角英文字母、全半角数字、全半角 ASCII 标点、半角片假名（含半角浊点/半浊点合成标准全角假名）、单字符省略号 `…`（归一为 `...`）、带圈数字（如 `①`→`1`）、上标/下标数字（如 `²`→`2`）、罗马数字字符（如 `Ⅱ`→`ii`），并统一不区分字母大小写。
     2. **补充同义标点映射（严格限定以下三项，其余标点保持原样不混同）**：
        - 日文波浪号 `〜`（U+301C）统一映射为 `~`（与全角波浪号 `～` 归一后的 `~` 互通）；
        - 居中省略号 `⋯`（U+22EF）统一映射为 `...`；
        - 西文弯单引号/撇号 `‘`、`’` 统一映射为 `'`，西文弯双引号 `“`、`”` 统一映射为 `"`（直角引号 `「`、`」` 与破折号 `—`、`―` 保持独立，不与双引号或连字符混同）。
     3. **空白字符折叠**：台词与搜索词内部的连续空白字符（含普通空格、全角空格 `　`、不换行空格、制表符、换行符）统一折叠为单个普通空格；搜索词额外去除首尾空白（去除首尾空白后为空则视为空搜索词）。
     4. **严格保留的语言区分边界**：不剥离西文重音符（如 `Mère` 与 `Mere`、`lässt` 与 `lasst` 保持区分），严格保留日文清浊音/半浊音与大小假名区分（如 `が`≠`か`、`っ`≠`つ`），严格保留平片假名区分与中文简繁体区分。

2. **纯字面连续子串匹配规则**
   - **取消一切隐式高级搜索语法**：用户输入中的 `*`、`""`、`'`、`AND`、`OR`、`NOT`、`NEAR` 等字符一律视为普通字面文本，不再解析为通配符或布尔操作符。
   - **全字符可检索与字面连续匹配**：所有中日韩文字（含日文叠字符 `々`、汉字零 `〇` 等）、西文字母、希腊/特殊字母、数字、标点与特殊符号（如 `...`、`♪`、`!`）均支持单独或组合检索；只要目标文本归一化后包含搜索词归一化后的完整连续子串（含搜索词内部的字面空格），即判定为命中。
   - **单条台词独立判定边界不变**：同一时间轴下包含多条独立台词（如双语字幕上下两条）时，仍以单条台词为单位独立判定匹配与统计，不跨同组相邻台词拼凑命中。

3. **全应用检索入口一致性与历史数据无缝生效**
   - 工作台 `Search`、播放页 `Command Panel` 搜索（及深链接搜索）、`Excerpt` 摘录集详情表内搜索、`Library` 文件夹概览标题搜索、`Excerpt` 摘录集列表概览标题搜索，以及筛选规则中的文本匹配统一采用上述归一化与连续子串规则。
   - 已入库的历史媒体库数据在版本升级后自动按新规则生效，无需用户手动重新扫描媒体文件夹。
   - 搜索性能保持零退步：常规词与高频词的真冷启动首屏响应及全量检索耗时相比修改前无明显退步。
   - 关联设计文档中的对应规则记录，待本次改动验收完成后再统一提交更新。

# 验收标准

1. **升级无缝生效验证**：在已有历史索引数据的媒体库上直接启动新版本应用，无需重新执行文件夹扫描索引，上述 `#01` ~ `#71` 场景即按「修改后」预期生效。
2. **核心检索场景验收**：
   - 搜索 `...`、`…`、`♪`、`!` 等纯标点符号可正常返回匹配结果，且 `...` 与 `…`、`~` 与 `～` / `〜`、`'` 与 `’`、`"` 与 `“”` 双向互通；
   - 搜索 `3`、`３`、`3万円` 均可命中 `３万円くらいなら。`，搜索 `sumimi`、`ｓｕｍｉｍｉ` 均可命中 `ｓｕｍｉｍｉの初華`；
   - 搜索 `Ave Mujica`、`の世界`、`万円`、`堂々`、`人々`、`don't`、`Mère`、`Pastel*Palettes`、`煎菜饼 AND 米饭`、跨行粘贴台词及英文/数字中间子串均可完整命中，同时 `Mere` 不误命中 `Mère`、`ありかとう` 不误命中 `ありがとう`、`"hello"` 不误命中不含引号的 `hello`。
3. **多入口一致性与性能验收**：同一句台词在 `Search`、`Command Panel` 与 `Excerpt` 表内搜索结果一致，`Library` 与 `Excerpt` 列表概览搜索同步遵循同一归一化边界（如日文清音不再误命中浊音标题）；高频词与常规词冷启动首屏及全量搜索流畅无明显退步。
