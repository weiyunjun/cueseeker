# 需求描述

## 1. 目标与性质

本需求是一次实现收敛，不改变任何用户可见行为。目标是让关联设计中的
层级与菜单规则在代码中各只有一个承载点，此后规则变化只需修改一处。

## 2. 层级登记表

1. 应用内维护唯一一份「当前打开的层」记录，层的种类与高低按
   《界面层级》清单。独立窗口与系统菜单栏不进入记录。
2. 「谁是最上层、输入归谁」与「某层是否被更高层覆盖、是否冻结」
   只由这份记录回答。
3. 分散在各菜单与浮层里的覆盖判断全部改为询问登记表；各层自身的
   打开与关闭状态仍归各自模块持有。
4. 收敛后，重复的覆盖判断不再保留，也不得新增同类判断。

## 3. 菜单闸门

1. 全应用只有一份菜单事件处理实现，统一负责：监视器的安装与卸载；
   上下键、回车与 Esc；菜单之外的按下（沿用已统一的外部按下规则）；
   滚轮（按《菜单模态》第 6 条的表格）；下层 Hover 与选中的冻结。
2. 五个菜单（Workbench 表格行右键菜单、Workbench 卡片与封面右键菜单、
   视频播放倍速菜单、Playback Overlay 选中文字菜单、Command Panel
   选中文字菜单）全部通过这份实现呈现与响应；各菜单只提供菜单项、
   挂靠对象与所属层。
3. 菜单之间允许的行为差异，只能来自关联设计中已记录的差异
   （如倍速菜单不禁止滚动）。设计中没有记录的差异视为缺陷。
4. 文字选择的拖拽过程不属于菜单事件，不并入闸门。

## 4. 行为基线

1. 迁移前后用户可见行为完全一致。迁移中若发现现有行为与关联设计
   不一致，停止并报告，不得顺手修正。
2. 预计关联设计文档无需内容变化；验收后如确认无行为差异，设计文档
   不做修改。

# 验收

1. 现有菜单相关自动化端到端用例全部通过。
2. 按 `20260825-UI-Menu Outside Press And Other Windows.md` 的验收清单
   复验五个菜单，结果与该需求验收时一致。
3. 分散的覆盖判断在代码中不再存在，覆盖问题只有登记表一个回答来源。
4. 菜单事件处理只有一份实现，五个菜单没有各自的监视器。
