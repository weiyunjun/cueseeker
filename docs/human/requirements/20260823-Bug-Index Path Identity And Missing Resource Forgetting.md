## 问题

添加 `/Volumes/Samsung/测试` 报错 `Library became unavailable before indexing started.`，
该目录内容正常。原因是实现使用了 Data.md 未定义的平台资源身份与绑定状态机，
把一条历史记录认了回来并判定为不可用，失败发生在扫描之前。

## 核心规则

本次扫描结果是当前唯一真相。

1. 资源身份只由路径和文件名决定。禁止平台文件身份、内容指纹、绑定状态、冲突记录
   参与任何身份判断或新旧判断。
2. 内容是否变化只依据文件大小和修改时间。
3. 完整扫描确认某个资源不在本次匹配关系中时，该资源退出，并删除其记录、派生数据，
   以及封面、观看状态、观看进度、播放历史等用户数据。
4. 已退出的资源以相同路径重新出现时视为新资源，分配新的永久 ID，不恢复任何历史数据。
5. 用户从 CueSeeker 移除资料库后重新添加同一绝对路径时，分配全新 LibraryID。
6. 唯一例外：被 Shiori 或其他用户持久数据引用的 Cue，退出前必须进入 Tombstone。
7. 观看状态、播放进度、播放历史必须以 VideoID 作为身份键，不得以路径作为身份键。
8. 禁止实现本需求与 Data.md 未定义的防御性规则。允许的失败处理仅限 Data.md
   “失败处理”一节的四种情况。

## 并发保护

不使用数据库持久令牌保护索引发布权，改由
`20260823-Engineering-Single App Instance Guard.md` 提供。

## 现有数据处理

1. 迁移前必须把现有观看进度与观看状态导出为文件交给用户，由用户后续手动同步。
2. 路径已被改写为虚拟地址的历史记录直接删除。
3. 迁移必须保留 Shiori、Tag 及其 Tombstone。

# 验收标准

1. 真实目录 Index 成功后移除，再次添加同一目录，Index 成功。
2. 子文件夹被删除并完成 Index 后以相同路径恢复并再次 Index，其封面、观看状态、
   观看进度、播放历史均不恢复，视频为新 ID。
3. 文件夹仍存在但已不含任何有效匹配时该文件夹退出，其自定义封面不保留。
4. 同路径同文件名文件的大小或修改时间变化时，继续使用原永久 ID 并重新索引内容。
5. 同路径同文件名文件的大小与修改时间均未变化时，不读取文件内容。
6. 扫描中途失败时不发布本次结果，Index 前状态完整保留。
7. 数据库发布失败时整体回滚。
8. 被 Shiori 引用的 Cue 在资源退出后存在对应 Tombstone；未被引用的 Cue 直接删除。
9. 迁移后数据库中不存在平台资源身份、内容指纹、绑定状态和冲突记录。
10. 现有索引、播放、Search、Shiori 和数据库测试继续通过。
