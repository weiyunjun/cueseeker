# 需求描述

1. **视频与剧集文件夹进入 Tombstone 及同路径恢复（不恢复 Recent 与文件夹 Resume 秩序）**：
   - 在执行 Index 或 Remove Folder 后，若某个视频不再位于有效配对中，但带有用户数据（存在播放进度、观看状态为「在看」或「已看完」、手动修改过单集封面或默认音频源），则转入 Tombstone 保留上述数据，同时清理自动生成的封面，并清空其近期播放记录（从 Recent 列表移除，且不再作为所在文件夹顶部的 `Resume` 集数）；没有任何用户数据的视频直接清理。
   - 若剧集文件夹下已无任何有效配对文件，但该文件夹设有用户手动修改的文件夹封面，同样按文件夹完整路径保留该手动封面（自动生成的文件夹封面直接清理）。
   - 当后续完全相同路径（路径、文件名、扩展名均一致）的视频或文件夹重新进入有效配对时，恢复其播放进度、观看状态、手动封面及默认音频源，但**不恢复 Recent 记录，也不改变所在文件夹顶部已有的 `Resume / Play` 秩序**。

2. **视频时长短于原播放进度时的统一重置规则**：
   - 无论是直接替换同路径同名视频并执行 Index，还是视频从 Tombstone 在同路径复活并执行 Index，只要读取到的新视频时长小于原播放进度，一律将播放进度清零，并将观看状态重置为「未观看」。

3. **Excerpt 台词进入 Tombstone 后不再夺回列表 Resume 锚点**：
   - 当 Excerpt List 当前指向的继续播放（`Resume`）台词进入 Tombstone 时，立即将该列表的继续播放锚点回退到列表中的第 1 条可用台词（若列表内已无可用台词则清空该列表的近期播放记录）；后续该台词从 Tombstone 复活时，保持现有的继续播放锚点不变，不跳回该台词。

# 验收标准

1. 对某文件夹设置手动文件夹封面，并对其中 `1.mkv` 产生播放进度（或标记为「在看」/「已看完」、设置手动单集封面）：
   - 在 App 中移除该文件夹（或在磁盘上删除/改名 `1.mkv` 后执行 Index），该视频从 Library 与 Recent 中消失；若同一文件夹下其它视频有播放历史，文件夹顶部 `Resume` 回退显示其它视频，否则显示 `Play`；
   - 重新添加该文件夹（或将 `1.mkv` 恢复原路径文件名并执行 Index），文件夹手动封面与 `1.mkv` 的单集手动封面、播放进度、观看状态均恢复，但 `1.mkv` 不会重新出现在 Recent 中，也不会改变文件夹顶部现有的 `Resume / Play` 集数。
2. 当 `1.mkv` 原有播放进度为 `15:00`（无论原本是「在看」还是「已看完」）：
   - 无论是在磁盘上直接用一个时长为 `05:00` 的同名 `1.mkv` 覆盖后执行 Index，还是先删除 `1.mkv` 执行 Index 再放入时长为 `05:00` 的同名 `1.mkv` 执行 Index，`1.mkv` 的播放进度均清零，且观看状态重置为「未观看」。
3. 在 Excerpt List 中播放第 10 条台词，随后使其进入 Tombstone（例如删掉对应视频或字幕后执行 Index），列表顶部 `Resume` 回退到第 1 条可用台词；随后恢复对应视频或字幕并执行 Index 使第 10 条台词复活，列表顶部 `Resume` 仍保持在第 1 条可用台词，不会跳回第 10 条。
