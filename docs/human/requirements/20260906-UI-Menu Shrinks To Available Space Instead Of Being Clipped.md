# 需求描述

## 1. 适用范围

Workbench 表格行菜单及其二级菜单、筛选菜单、封面卡片右键菜单。

## 2. 高度

1. 菜单高度取三者中的最小值：内容自然高度、`--max-height-menu`、菜单所在一侧的可用空间。
2. 因可用空间而收缩时，按现有规则出 Vertical Scrollbar，菜单同样按现有规则加宽，Item Stack 宽度不变。
3. 可用空间由各菜单自己的边界决定：

| 菜单 | 边界 |
| --- | --- |
| 表格行菜单及其二级菜单 | 表格正文可视区 |
| 筛选菜单 | 页面内容列 |
| 封面卡片右键菜单 | 页面可视区 |

4. 可用空间极小时不设下限，也不改用其它边界，按第 2 条出滚动条。

## 3. 方向

1. 默认朝下。
2. 下方可用空间放不下自然高度时朝上。
3. 两侧都放不下自然高度时，取可用空间较大的一侧。
4. 方向与高度都只在弹出的瞬间确定一次，之后不再重算。

## 4. 裁剪

1. 表格行菜单的裁剪只服务于「跟随」：挂靠对象随表格滚动或窗口缩放而移动时，菜单越过表格正文区边界的部分被裁掉，方向与高度不变。
2. 弹出的瞬间不允许出现裁剪。

## 5. 二级菜单

1. 二级菜单同样受第 2 节约束。
2. 二级菜单不做上下翻转，仍与父项对齐并夹进边界，只在高度上收缩。

## 6. 保持不变

1. 挂靠、跟随、菜单内外交互沿用
   `docs/human/requirements/20260824-UI-Menu Placement And Outside Interaction.md`。
2. 不新增、不修改任何 Token。
3. 菜单的配色、圆角、阴影、内边距与滚动条位置不变。
4. 空间与内容都充裕时，菜单的高度、宽度与位置不变，不出滚动条。

# 验收

1. 压低窗口高度使下方放不下：菜单朝上弹出，完整显示，不被裁。
2. 继续压低使两侧都放不下：菜单落在可用空间较大的一侧，高度贴满该侧空间，
   出现滚动条并加宽，没有任何一项被切掉。
3. Shiori 列表足够多时打开二级菜单：高度不超过表格正文区，出现滚动条，
   底部不被切。
4. 菜单打开后滚动表格：菜单随行平移，越过表格正文区边界的部分仍被裁掉，
   方向与高度不变。
5. 筛选菜单与封面卡片右键菜单在窗口压低时同样收缩并出现滚动条，不被裁。
6. 空间与内容都充裕时菜单外观与位置没有变化。
7. 高亮、键盘导航与菜单内外交互没有回归。
8. 第 1、2、5 条需要改变窗口高度，现有 Debug E2E 控制器没有窗口高度命令，
   走人工验收；其余使用现有自动化端到端测试覆盖，不为本需求新增鼠标能力。

   并收缩滚动」；「Workbench 表格行菜单以表格正文区域为边界，超出部分被裁剪」
   订正为只适用于跟随。
