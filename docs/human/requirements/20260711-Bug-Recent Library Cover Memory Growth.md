main

# 需求描述
1. 在保留原始分辨率Master封面图的情况下，统一生成并解码，保持原始比例的（不拉伸、不补边），宽度最大512px，高度最大288px的JPG格式的只用于展示的封面图。
2. 源图尺寸足够时，保持原始比例缩放至完整落入512×288 bounding box，至少一边达到对应上限；生成阶段不裁切、不拉伸、不补边。
3. 不管App窗口如何缩放，始终渲染该尺寸的封面图，避免内存占用问题。
4. 本需求覆盖此前“按实时显示像素downsample”的规则。窗口缩放只改变显示frame，始终复用同一展示派生图和解码版本，不重新生成或解码。

# 验收流程
使用Activity Monitor UI中的内存数据作为标准。
1. Search → Recent → Library一级。
2. 进入集数最多的30集文件夹，完整滚动二级页面。
3. 返回一级，再访问另外3–5个文件夹。
4. 重复第2和第3步完整流程4次。
5. 最后缩小并恢复窗口5次。

# 验收标准：
1. 第一轮完成后的内存稳定值记为 M1。
2. 重复5轮：M2 - M1 ≤ 5MB。
3. 窗口缩放后：M3 - M1 ≤ 10MB。
4. 绝对稳定值不超过75MB。
