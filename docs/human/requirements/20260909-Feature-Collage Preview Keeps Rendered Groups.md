# 版本
main

# 需求描述
1. 现状：在 Collage 中勾选或取消勾选字幕时，每次改动都会取消正在进行的渲染，并以最后一次成功发布的结果为基准重新比对。被取消的那一批里已经渲染完成的组会随任务一起丢弃。
2. 由此产生两个问题：连续勾选期间画面完全不动，没有任何中间结果；已经渲染过的组会被反复重渲，点击越快浪费越多。
3. 目标：让已经渲染完成的组在请求被取消后仍然可用，使下一次改动只渲染真正缺少的组。不改变任何界面行为、交互和输出结果。
4. 本次不改发布粒度，仍然是整批渲染完成后一次性更新预览。逐组发布留待这次的体验结果出来后再决定。
5. Collage 的时间戳合并、排序、分组、中点计算和取帧方式维持现状，本需求不修改，参考 20260730-Feature-Playback Current Collage Editor.md 和 20260909-Feature-Collage Render Latency.md。

# 改动内容
1. 渲染结果按组内容为键缓存，缓存跨请求存活，请求被取消时不清除。新的选择计划只渲染缓存中没有的组，其余直接取用。
2. 现有依赖"上一次成功发布结果"的前后缀复用由该缓存取代，不再保留两套复用逻辑。
3. 缓存范围受控：每次成功发布后只保留当前选择计划中的组，退出 Collage 时清空。

# 数据要求
1. 改动前先重新测量基准，样本仍为 It's MyGO!!!!! 第 05 集。
2. 测量两种情形并分别记录：单条勾选后画面更新的耗时；以及在上一次更新尚未完成时连续追加勾选，从最后一次勾选到画面更新的耗时。连续勾选的条数在测量时记录。
3. 记录同一轮操作中实际渲染的组次数，用于确认重复渲染是否消除。该计数通过临时日志读取，测量完成后移除，不进入最终提交；因此改动后的数据在带日志的构建上测得，与提交的代码仅差这一行日志。
4. 记录改动前后的内存占用，以 phys_footprint 为准，确认缓存没有带来额外增长。
5. 改动后用同一样本、同一方法复测上述全部项目，并给出改动前后的对比。

# 修改流程
## 1. 记录改动前的基准数据
## 2. 渲染结果改为按组缓存，回归 Collage 输出结果，并记录数据
## 3. 对比改动前后，给出结论
