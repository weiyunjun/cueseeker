# 需求描述
1. 现在的项目进度已经初步脱离了demo阶段，进入到流程较为正式的阶段了。之后的规则和文档将主要通过docs/human/design来维护更新，新的需求仍然要建立需求单，但内容会主要引用docs/human/design的固化文档。
2. docs/human/design，主要的任务在于对齐需求，明确流程，理清可能产生歧义的地方。对于一些实现已经非常普遍，有着明确的公认的做法的模块，仅添加有必要说明的内容。这是基于效率考虑。因为实践经验表明，花10个小时写一个这些论文般严谨的文档，对项目开发帮助有限，真正有帮助的地方在于反复试错。
3. 架构调整，是现阶段的重要任务，因为核心功能已经开发完毕，但是细节部分还有很多不完善的地方，架构本身的问题会大大影响开发效率。
