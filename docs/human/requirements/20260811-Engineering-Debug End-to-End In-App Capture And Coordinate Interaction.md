# 版本

main

# 需求描述

改进 CueSeeker macOS App 的端到端测试能力，使测试能够直接捕获 CueSeeker 当前实际显示的完整界面，并按照已知坐标执行交互。

当前 Debug 截图只捕获主窗口的 Content View，无法包含独立窗口、Sheet、Popover 等实际可见界面。例如：

1. Shiori Editor 通过 Sheet 显示。
2. Settings 通过独立窗口显示。
3. Text Field、Text Area、Number Field 等控件可能位于这些窗口中。
4. 仅捕获主窗口时，生成的截图与用户实际看到的界面不一致。
5. 根据代码重新绘制或重建界面不能作为真实截图证据。

本需求要求 Debug App 直接捕获 macOS WindowServer 已经合成完成的 CueSeeker 实际界面。截图必须反映截图时真实显示的窗口、内容、位置、层级和遮挡关系，不得通过代码重新构造界面。

# 需求目标

1. Debug App 自带按需截图能力，不调用外部截图工具。
2. 截图直接来自 CueSeeker 当前实际显示的窗口合成结果。
3. 截图包含所有当前可见、由 CueSeeker 进程拥有的界面。
4. 端到端测试能够按照完整界面的已知坐标直接模拟点击。
5. 截图只用于验证结果，不用于识别控件或计算点击位置。
6. 该能力仅用于 Debug 端到端测试，不影响正常 Debug 使用和 Release App。

# 实际界面截图

一次截图必须捕获截图时 CueSeeker 当前实际显示的完整界面，包括但不限于：

1. 主窗口。
2. 主窗口上显示的 Sheet。
3. Settings 等独立窗口。
4. CueSeeker 进程拥有的 Panel、Popover 和系统标准窗口。
5. 窗口标题栏和窗口装饰。
6. 窗口之间的实际位置、前后层级和遮挡关系。
7. 当前 Text Field、Text Area、Number Field 等输入控件的真实内容。
8. 当前焦点、选中状态、禁用状态、校验提示和其他可见状态。
9. 播放界面实际显示的视频帧、字幕和应用界面。

截图不得：

1. 只捕获某一个窗口的 Content View。
2. 将主窗口、Sheet 或 Settings 分别输出为互相独立的截图来替代实际界面。
3. 根据 SwiftUI 或 AppKit 代码重新绘制界面。
4. 临时插入替代视图来伪造截图内容。
5. 使用业务数据重新生成截图。
6. 在截图失败时回退到旧的 Content View 截图。
7. 静默遗漏当前实际可见的 CueSeeker 窗口。

# 截图实现约束

1. Debug App 使用 macOS ScreenCaptureKit 获取实际窗口合成结果。
2. ScreenCaptureKit 只捕获 CueSeeker 进程拥有的窗口，不捕获其他应用或桌面内容。
3. 截图范围覆盖当前可见 CueSeeker 窗口形成的完整界面区域。
4. 截图时不得改变窗口位置、大小、层级、焦点或当前业务状态。
5. 截图默认不包含鼠标指针。
6. 截图应保持当前显示比例，不得产生非预期拉伸。
7. 截图结果应保存为 PNG。
8. 截图结果应返回文件路径、逻辑尺寸、像素尺寸、缩放比例和当前窗口布局信息。
9. 所有需要进入同一截图的 CueSeeker 窗口应位于同一显示器；不满足时应明确失败，不得生成不完整截图。
10. 截图时 CueSeeker 应处于前台，且不得被其他应用窗口遮挡。

# Screen Recording 权限

1. Debug 实际界面截图允许使用 macOS Screen Recording 权限。
2. 权限仅用于 Debug 端到端测试截图。
3. 启动 Debug E2E 功能时应检查权限状态。
4. 权限未授权时，应明确返回权限错误和处理说明。
5. 权限授权后需要重新启动 App 时，应明确提示。
6. 权限被拒绝或不可用时，不得回退到 Content View 截图、代码重建图或外部截图工具。
7. Release App 不得包含或触发该 Debug 截图流程。

# 完整界面坐标

1. 截图和坐标点击使用同一个完整界面坐标系。
2. 坐标原点为完整 CueSeeker 截图区域的左上角。
3. X 坐标向右增加，Y 坐标向下增加。
4. 点击坐标使用逻辑点，不直接使用截图像素。
5. 截图结果必须返回逻辑尺寸、像素尺寸和缩放比例。
6. 当前窗口布局变化后，必须更新完整界面范围和坐标信息。
7. 点击位置必须命中该坐标下最前方的可见 CueSeeker 窗口。
8. 点击事件应转换到目标窗口的本地坐标后，通过正常 AppKit 事件处理发送。
9. 点击不得直接调用目标控件操作、业务方法或修改业务状态。
10. 点击位于 CueSeeker 可见界面之外时应明确失败。

# Debug E2E 控制

Debug E2E 功能继续通过显式启动参数启用。

启用后应支持：

1. 查询当前完整界面的逻辑尺寸、像素尺寸、缩放比例和窗口布局。
2. 按需生成当前实际界面截图。
3. 按完整界面逻辑坐标发送左键点击。
4. 返回每次操作的成功或失败结果。
5. 在窗口布局发生变化后返回新的界面信息。

所有返回结果应能够明确区分：

1. 操作成功。
2. Screen Recording 权限不可用。
3. 当前没有可捕获的 CueSeeker 窗口。
4. CueSeeker 窗口分布在多个显示器。
5. 点击坐标越界。
6. 截图生成或保存失败。
7. 当前界面状态已经变化，原坐标条件不再成立。

# 测试原则

1. 对于布局和位置已知的 CueSeeker UI，测试直接使用预先确定的坐标操作。
2. 不得通过截图、OCR、图像识别或模板匹配寻找控件。
3. 截图是操作前后状态的真实验证证据，不是测试导航方式。
4. 测试流程必须声明对应的完整界面尺寸和窗口布局前提。
5. 实际界面与测试前提不一致时应停止测试，不得临时根据截图重新计算坐标。
6. 日志、业务状态、播放状态和数据结果仍应按照测试目标单独验证，不能全部由截图替代。
7. 代码重建图、设计稿和模拟图不得标记为真实运行截图。

# 验收标准

1. Debug App 可以生成当前 CueSeeker 实际显示界面的完整 PNG。
2. 只有主窗口时，截图与当前主窗口实际显示结果一致。
3. 打开 Shiori Editor 后，截图同时包含主窗口和实际显示的 Sheet。
4. Shiori Editor 截图真实包含 Text Field 和 Text Area 的当前内容。
5. 打开 Settings 后，截图按照实际位置和层级包含主窗口与 Settings 窗口。
6. Settings 截图真实包含 Number Field 的当前内容。
7. 控件获得焦点、内容修改或出现校验状态后，截图能够反映对应的真实变化。
8. 播放界面截图直接包含实际显示的视频帧、字幕和窗口界面。
9. 截图能够保留窗口之间的实际位置、层级和遮挡关系。
10. 截图过程不改变窗口位置、大小、焦点、层级或业务状态。
11. 测试可以使用完整界面的已知逻辑坐标执行左键点击。
12. 当多个 CueSeeker 窗口重叠时，点击命中该位置最前方的窗口。
13. 坐标点击触发与正常鼠标点击一致的 AppKit 和 SwiftUI 界面行为。
14. 坐标点击不直接调用业务操作或修改业务状态。
15. 测试不需要移动真实鼠标或取得 Accessibility 权限。
16. 测试不需要根据截图定位控件。
17. Screen Recording 权限不可用时，截图明确失败且不产生替代截图。
18. 当前 CueSeeker 窗口跨越多个显示器时明确失败，不产生不完整截图。
19. 普通 Debug 启动不主动执行截图流程。
20. Release App 不包含或启用该 Debug E2E 截图和坐标交互能力。
21. Text Field、Text Area 和 Number Field 的“修改前”与“修改后”截图均来自真实运行界面，不得根据代码重建。
