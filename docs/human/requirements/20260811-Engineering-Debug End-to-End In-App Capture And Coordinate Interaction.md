# 版本

main

# 需求描述

改进 CueSeeker macOS App 的端到端测试方式。

当前测试经常依赖系统截图，再根据截图机械地寻找界面元素和操作位置。这种方式没有利用应用界面已知这一前提，并且过度依赖外部桌面环境。

本需求要求：

1. Debug App 自带按需截图能力，能够直接捕获当前 CueSeeker 界面。
2. 端到端测试能够按照已知的应用内坐标直接模拟点击。
3. 截图用于确认操作结果，不用于识别控件或计算点击位置。
4. 已知界面的操作流程不得默认依赖系统截图、桌面图像识别或外部鼠标控制。

# 修改范围

1. 为 macOS Debug App 增加应用内截图能力。
2. 截图应覆盖当前可见的 CueSeeker 界面。
3. 播放界面截图应包含当前视频帧、字幕和应用内界面。
4. 为 macOS Debug App 增加应用内坐标点击能力。
5. 点击位置使用统一、明确的窗口内坐标基准。
6. 坐标点击应经过正常的界面事件处理，不得直接修改业务状态或调用目标操作。
7. 该能力仅用于开发和端到端测试，不得影响正常 App 行为或 Release 版本。

# 测试原则

1. 对于布局和位置已知的 CueSeeker UI，测试应直接使用预先确定的坐标操作。
2. 不得通过反复截取系统屏幕来寻找目标控件。
3. 不得通过 OCR、图像识别或截图匹配计算点击位置。
4. 应用内截图是操作前后状态的验证证据，不是测试导航方式。
5. 日志、业务状态、播放状态和数据结果仍应按照各自测试目标进行验证，不能全部由截图替代。

# 验收标准

1. Debug App 可以根据测试需要生成当前 CueSeeker 界面的截图。
2. 截图过程不依赖外部截图工具或系统桌面截图流程。
3. 普通界面截图能够正确反映当前可见状态。
4. 播放界面截图能够正确包含视频帧、字幕和当前可见的应用内界面。
5. 测试可以使用已知的窗口内坐标完成左键点击。
6. 坐标点击能够触发与正常鼠标点击一致的界面行为。
7. 坐标点击不直接调用业务操作或修改业务状态。
8. 测试不需要根据截图定位控件。
9. 测试不需要移动真实鼠标或取得系统辅助功能权限。
10. 正常 Debug 使用和 Release App 不受该测试能力影响。
11. 现有适合坐标操作的端到端测试流程改为使用该能力。
