# 需求描述
1. 现状：20260909-Feature-Collage Preview Keeps Rendered Groups.md 已消除同一组的重复渲染，但连续勾选后的等待只从约 1.94s 降到约 1.69s。原因是最后一次勾选之后仍未渲染的组只能逐个串行渲染，等待时间等于这些组的耗时之和。
2. 每组的取帧和字幕渲染相互独立，机器有多个性能核。基准测量中同一组的并发副本只使内存峰值增加约 13MB。
3. 目标：连续勾选后的等待接近单组耗时，而不是待渲染组数的倍数。不改变任何界面行为、交互和输出结果，仍然整批渲染完成后一次性更新预览。
4. 现有缺陷一并修正：某组渲染失败而选择计划已变化时，渲染循环会退出并停留在渲染中状态，直到下一次勾选才恢复。
5. Collage 的时间戳合并、排序、分组、中点计算和取帧方式维持现状，参考 20260730-Feature-Playback Current Collage Editor.md。

# 改动内容
1. 渲染循环每一轮把当前选择计划中缓存里没有的组一起发起渲染，同时渲染的组数上限为 4。每组渲完立即入缓存，整批完成后再重读最新计划决定下一轮。
2. 同一组在任意时刻仍然只有一份渲染工作，正在渲染的批次不被打断，退出 Collage 或关闭播放时在批次边界停下，不得拖住退出。
3. 某组渲染失败时，若选择计划已变化，循环按最新计划继续；若未变化，才报告错误并清空预览。
4. 缓存的键、保留范围和清空时机维持 20260909-Feature-Collage Preview Keeps Rendered Groups.md 的规定。

# 数据要求
1. 样本仍为 It's MyGO!!!!! 第 05 集，方法与 20260909-Feature-Collage Preview Keeps Rendered Groups.md 相同：单条勾选后画面更新的耗时；连续勾选 5 条，从最后一次勾选到画面更新的耗时；该轮实际渲染的组数；phys_footprint 及峰值。
2. 基准直接沿用该需求单记录中“缓存 + 不打断当前组”一列，不重新测量。
3. 渲染组数仍通过临时日志读取，测量完成后移除，不进入最终提交。
4. 改动后复测全部项目，给出对比。若等待没有明显缩短，停下来报告，不追加其他手段。
