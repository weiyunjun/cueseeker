# 需求描述

## 本次结论

本需求修复索引流程中已经确认的七个问题：

1. 部分 Cue 退出路径没有统一执行 Tombstone 保护，可能造成 Shiori 引用失效。
2. 单个字幕文件读取或解析失败会中止整个 Library 的发布。
3. Library 完整扫描成功前已经修改永久身份和媒体绑定。
4. Library 平台文件身份暂时不可取得时，没有清除数据库中的旧平台身份。
5. 字幕准备与数据库发布使用了不同时间取得的文件状态，可能混合旧内容和新文件身份。
6. 视频目录读取失败被错误地解释为目录中没有匹配视频。
7. SRT 去重和 ASS Cue Group 使用原始时间字符串，而不是标准化后的实际时间。

本需求不改变永久身份规则：

- Subtitle 和 Video 的新旧文件判断以路径和文件名为准。
- 同路径、同文件名的文件始终视为原文件，继续使用原永久 ID。
- 文件大小、修改时间或内容发生变化时，重新读取并索引文件内容。
- 保存方式、原子替换或文件系统行为导致平台文件身份变化时，只更新当前平台身份，不得产生新的永久 ID。
- 平台文件身份不得覆盖基于路径和文件名作出的新旧文件判断。
- 路径或文件名不同的文件按照新资源处理，获得新的永久 ID。
- 新资源不得继承旧资源的 Shiori 或其他用户持久数据。
- 旧资源退出当前有效索引时，必须保护其被 Shiori 或其他用户持久数据引用的 Cue。

## 一、统一 Cue 退出与 Tombstone 保护

任何 Cue 从当前有效数据中退出前，都必须执行统一的持久引用检查。

该规则适用于所有 Cue 退出路径，包括：

1. 同一 SubtitleID 的字幕内容更新。
2. 字幕文件缺失。
3. Library 被用户移除。
4. 路径或文件名变化导致原资源退出当前索引。
5. 文件重新绑定、身份冲突处理或其他资源退役流程。
6. 数据库清理或索引重建中删除旧 Cue 的流程。

处理规则：

- 被 Shiori 或其他用户持久数据引用的旧 Cue 必须进入 Tombstone。
- Tombstone 保留原 CueID、原 SubtitleID、最后有效文字、时间范围、Cue Group Snapshot 和不可用原因。
- 未被任何用户持久数据引用的旧 Cue 可以删除。
- 新资源使用新的 SubtitleID 和 CueID，不继承旧资源的 Shiori 或其他用户数据。
- Tombstone 保护必须由统一的数据生命周期入口保证，不能由各个调用者自行选择是否执行。
- 数据库不得出现一个 Shiori 引用的 Cue 同时不存在于有效 Cue 和 Tombstone 中的状态。
- 有效 Cue 和 Tombstone 不得同时包含同一个 CueID。

### 同路径字幕内容更新

同路径、同文件名的字幕内容发生变化时：

- 必须继续使用原 SubtitleID。
- 平台文件身份变化不得触发 SubtitleID 替换。
- 新旧 Cue 必须在同一 SubtitleID 下执行既有 Cue 对账流程。
- 未发生逻辑变化的 Cue 继续使用原 CueID。
- 只有文字内容发生变化，并符合既有本地编辑匹配规则的 Cue，继续使用原 CueID。
- 继续使用原 CueID 的 Shiori 必须保持可用，并展示更新后的当前内容。
- 无法与新内容匹配、需要退出当前索引的旧 Cue，按照统一 Tombstone 规则处理。
- 不得因为平台文件身份变化而把同路径文件的全部旧 Cue 判定为来自已替换资源。

### 现有损坏数据处理

本次修改必须处理已经存在的悬空 Shiori，包括此前发现的 Shiori List 3 原第 44 个项目。

处理规则：

- 保留原 Shiori 和原 CueID。
- 当前字幕中能够确认存在对应 Cue 时，恢复为有效 Cue。
- 当前字幕中不存在对应 Cue 时，为原 CueID 恢复或补建 Tombstone。
- 不得把 Shiori 直接改绑到错误生成的新资源 CueID。
- 只能使用能够确认的历史数据或最后有效快照恢复内容。
- 无法确认完整内容时，仍须保留 Shiori 和最小不可用占位，不得静默隐藏或删除。
- 修复后不得存在 Shiori 引用既非有效 Cue、也非 Tombstone Cue 的情况。

## 二、隔离单个字幕文件失败

索引必须区分 Library 扫描失败和单个字幕文件处理失败。

### Library 扫描失败

以下情况属于扫描不完整：

- Library 根目录不可访问。
- NAS 断开。
- 权限不足。
- 目录枚举失败或只完成部分枚举。
- 无法可靠确定本次完整文件集合。

处理规则：

- 立即取消本次 Library 核心索引发布。
- 保留上一次成功索引的全部状态。
- 不得产生文件缺失、资源退出或数据删除结论。

### 单个字幕文件失败

已经通过完整扫描确认文件存在，但发生以下错误时，只跳过该文件：

- 文件属性读取失败。
- 文件内容读取失败。
- 字幕编码解码失败。
- 整个字幕文件解析失败。
- 文件在准备过程中发生变化，无法确认本次解析结果对应的文件状态。

处理规则：

- 保留该文件上一次成功索引的全部数据和绑定状态。
- 新文件处理失败时，不发布该文件的不完整数据。
- 失败文件不得被解释为缺失或删除。
- 同一个 Library 中其他成功处理的文件继续正常发布。
- Index 结果记录失败文件路径和失败原因。
- 数据库核心发布失败仍然回滚整个 Library 本次发布，不能按单文件提交部分数据库结果。

## 三、调整 Library 身份与完整扫描的事务边界

在确认 Library 扫描完整成功以前，不得发布以下变化：

- Library 永久身份替换或退役。
- Library 平台文件身份更新。
- Library 路径重新绑定。
- Folder、Video 或 Subtitle 的 LibraryID 回填。
- 因本次扫描产生的资源缺失、退出或删除状态。

Index token 或运行状态可以在扫描前建立，但不能把未完成扫描产生的身份和媒体变化作为成功状态发布。

处理规则：

1. 先确认 Library 根目录可访问。
2. 完成字幕与视频匹配所需的完整目录扫描。
3. 准备字幕解析结果和文件状态变化。
4. 扫描或准备失败时，放弃尚未发布的身份和索引变化。
5. 扫描完整成功后，在核心发布事务中统一提交 Library 身份、媒体绑定、Cue、Search 和排序数据。

用户选择的 Library 地址可以保留为配置，但扫描失败不得退役或覆盖上一次成功绑定的 Library 永久身份和媒体数据。

## 四、修正平台文件身份处理

数据库保存的旧平台文件身份或本次读取的当前平台文件身份中，任意一侧无法取得时，按照路径和文件名规则处理。

处理规则：

- 同一路径、同一文件名继续使用原永久 ID。
- 当前平台文件身份能够取得时，将当前值保存到原永久 ID。
- 当前平台文件身份无法取得时，必须将数据库保存的平台文件身份更新为空。
- 不得继续使用无法验证的旧平台文件身份作为当前或后续文件的身份凭据。
- 平台文件身份以后重新可得时，将重新取得的身份绑定到原永久 ID。
- 数据库旧平台身份和当前平台身份即使不同，也不得把同路径、同文件名的文件判定为新资源。
- 平台文件身份只用于记录和验证当前文件状态，不参与覆盖基于路径和文件名作出的永久身份判断。
- 根据平台文件身份查找到其他记录时，当前精确路径记录必须优先。
- 平台文件身份冲突不得导致当前精确路径记录被错误退役。

该规则必须覆盖 Subtitle 和 Video。

Library 平台身份暂时不可取得时，也必须清除数据库中的旧平台身份；重新取得后继续绑定原 LibraryID。

## 五、保证字幕内容与文件状态来自同一次观察

一次字幕索引结果中的以下数据必须对应同一个文件状态：

- 平台文件身份。
- 文件大小。
- 修改时间。
- 解码后的字幕内容。
- Cue、Cue Group 和其他字幕派生数据。
- 数据库最终保存的文件状态。

处理规则：

1. 准备阶段记录读取字幕内容时对应的平台文件身份、文件大小和修改时间。
2. 内容读取和解析完成后，重新验证平台文件身份、文件大小和修改时间。
3. 文件在处理过程中发生变化时，本次结果作废，按照单文件失败处理。
4. 数据库发布阶段使用已经验证的准备结果，不得重新读取另一个时间点的平台文件身份并与旧解析结果混合。
5. 同路径文件变化不得导致旧内容被绑定到新生成的永久 ID。
6. 无法获得原子文件快照时，系统只需保证不会发布已经确认前后不一致的数据，不要求锁定或修改用户源文件。

## 六、区分视频目录读取失败与没有匹配视频

视频匹配流程不得使用空数组表示目录读取失败。

处理规则：

- 视频目录成功读取，且没有符合扩展名和匹配规则的视频时，才判定为没有匹配视频。
- 视频目录枚举失败、权限不足或读取不完整时，属于扫描不完整，取消本次 Library 核心索引发布并保留上一次成功状态。
- 某个候选文件的必要属性无法读取，导致无法确定它是否为有效视频候选时，不得静默忽略；本次扫描必须报告失败。
- 非视频文件、目录、隐藏文件或不支持的视频扩展名仍可正常忽略。
- 视频读取失败不得产生错误的 missing video、字幕解绑、视频退役或展示数据清理结果。

## 七、使用标准化时间进行逻辑去重和分组

原始字幕时间字符串只属于源格式信息，不参与数据库逻辑身份、去重或 Cue Group 分组。

### SRT

SRT 逻辑 Cue 去重依据为：

- 标准化后的开始毫秒。
- 标准化后的结束毫秒。
- 经过既定字幕处理后的文字内容。

两个时间字符串写法不同，但解析后的开始和结束毫秒相同时，视为相同时间范围。

SRT 序号和原始时间字符串不得阻止完全相同 Cue 的去重。

### ASS

ASS Cue Group 依据同一 SubtitleID 下的以下数据建立：

- 标准化后的开始毫秒。
- 标准化后的结束毫秒。

两个 ASS Dialogue 的原始时间字符串写法不同，但解析后的毫秒时间相同时，属于同一时间范围，可以进入同一个 Cue Group。

ASS 的 Style、文字和其他 Dialogue 字段继续按照现有 Cue 身份规则处理。原始时间字符串可以为渲染或源格式保真保留，但不得参与逻辑 Cue Group Key。

# 验收标准

1. 同路径、同文件名的字幕通过普通保存或原子替换更新后：
   - 原 SubtitleID 保持不变。
   - 平台文件身份更新为当前值。
   - 平台文件身份变化不产生新的 SubtitleID。
   - 文件大小、修改时间或内容变化能够触发重新读取和索引。
   - Cue 在原 SubtitleID 下执行对账。
   - 未发生逻辑变化的 Cue 保持原 CueID。
   - 只有文字内容变化并符合既有本地编辑规则的 Cue 保持原 CueID。
   - 对应 Shiori 保持可用并展示更新后的当前内容。
   - 退出当前索引且被引用的旧 Cue 进入 Tombstone。
2. 路径或文件名不同的新资源：
   - 获得新的 SubtitleID 和 CueID。
   - 不继承其他资源的 Shiori 或用户持久数据。
   - 原资源退出索引时，被引用的 Cue 进入 Tombstone。
3. 任意字幕删除、缺失或退役入口执行后，不存在悬空 Shiori。
4. 已存在的悬空 Shiori 修复后：
   - 当前字幕中存在对应 Cue 时恢复为有效 Cue。
   - 当前字幕中不存在对应 Cue 时存在对应 Tombstone。
   - 不得直接改绑到错误生成的新 CueID。
5. 一个 Library 同时包含正常字幕和读取或解析失败字幕时：
   - 正常字幕成功发布。
   - 失败字幕保留上一次成功数据。
   - Index 结果列出失败文件及原因。
6. Library 目录枚举中途失败时：
   - 不发布本次核心索引。
   - LibraryID、平台身份、媒体绑定、Cue、Search 和排序保持 Index 前状态。
7. Library 平台文件身份经历“可得 → 不可得 → 再次可得”时：
   - 永久 LibraryID 保持不变。
   - 不可得阶段数据库平台身份为空。
   - 恢复后当前平台身份绑定到原 LibraryID。
8. 字幕在内容读取与发布之间发生变化时：
   - 不发布前后状态不一致的字幕结果。
   - 不把旧解析数据绑定到另一个文件状态。
   - 其他正常字幕仍可发布。
9. 视频目录读取失败时：
   - 不得被报告为没有匹配视频。
   - 不得产生视频缺失或解绑结果。
   - 保留上一次成功索引。
10. SRT 使用不同合法时间字符串表达相同毫秒时间时，完全相同文字只产生一个逻辑 Cue。
11. ASS 使用不同合法时间字符串表达相同毫秒时间时，相关 Cue 进入同一个 Cue Group。
12. 数据库完整性检查必须确认：
   - 每个 Shiori 引用的 Cue 存在于有效 Cue 或 Tombstone。
   - 有效 Cue 和 Tombstone 不同时包含同一个 CueID。
   - 新资源没有继承其他资源的用户数据。
   - 同路径文件的平台身份变化没有产生重复 SubtitleID、VideoID 或重复索引数据。
13. 全部现有索引、播放、Search、Shiori 和数据库测试继续通过。

# 必须增加的回归测试

1. 同路径、同文件名、平台文件身份变化时保留原 SubtitleID 的测试。
2. 同路径字幕通过原子替换保存后保留原 SubtitleID 的测试。
3. 同路径字幕只修改 Cue 文字时保留原 CueID，并保持 Shiori 可用的测试。
4. 同路径字幕内容更新导致部分旧 Cue 退出时，引用 Cue 进入 Tombstone 的测试。
5. 当前精确路径记录与其他平台身份记录冲突时，精确路径记录优先且不被退役的测试。
6. 同路径 Video 平台文件身份变化时保留原 VideoID 的测试。
7. 路径或文件名不同的新资源获得新永久 ID，且不继承用户数据的测试。
8. 所有字幕删除、缺失和退役入口的 Tombstone 不变量测试。
9. 现有悬空 Shiori 数据修复测试。
10. 同一 Library 中正常字幕与读取失败字幕并存的部分成功测试。
11. 同一 Library 中正常字幕与解析失败字幕并存的部分成功测试。
12. 扫描完成前失败不会修改 Library 身份和媒体绑定的测试。
13. Library 平台身份“可得 → 不可得 → 再次可得”的测试。
14. 字幕在准备期间被修改或替换的测试。
15. 视频目录枚举失败和候选属性读取失败的测试。
16. SRT 不同时间字符串、相同毫秒时间的去重测试。
17. ASS 不同时间字符串、相同毫秒时间的 Cue Group 测试。
18. 数据库发布失败继续整体回滚的回归测试。
19. 较旧 Index 不能覆盖较新 Index 的回归测试。

# 本次不处理

1. 不处理父子 Library 或其他路径重叠问题。
2. 不增加父子 Library 重叠限制。
3. 不修改自动封面失败后的重试规则。
