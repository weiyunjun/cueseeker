# 需求描述

1. **打开视频进入播放页时无主线程阻塞**：
   - 从 `Recent` 或 `Library` 点击视频卡片进入播放页（或打开本地/远程视频文件）时，播放页界面立即展开并保持可交互状态；
   - 关闭旧视频、读取视频文件、初始化解码与音频输出、以及定位到起始播放时间点的全过程均不阻塞界面响应，待目标画面首帧就绪后同步更新画面、当前时间与总时长；
   - 若等待首帧画面耗时超过既有加载反馈延迟阈值（`300ms`），按既有规则在播放舞台中央展示加载 Spinner，画面就绪或加载失败时立即消失。

2. **进入播放页时不触发被遮挡主界面的即时重刷**：
   - 打开视频进入播放页并记录最近观看时，不在打开视频的过程中等待观看历史写入完成，也不立即重刷被播放页遮挡的 `Recent` 与 `Library` 列表视图，待退出播放页或需要展示最新观看记录时再同步刷新。

3. **消除首次打开视频与打开准备阶段的重复开销**：
   - 应用启动后首次点击视频卡片与后续点击视频卡片保持一致的流畅切入体验，不在首次点击时产生额外的初始化卡顿；
   - 打开视频过程中不重复查询同一视频的起播进度、默认字幕、默认音轨及编码元数据。

# 验收标准

1. **点击卡片立即流畅进入播放页**：应用启动后首次及后续从 `Recent` 或 `Library` 二级目录点击高码率大体积视频卡片（无论从头播放还是从历史进度恢复播放）时，播放页立即平滑展开，打开媒体与解码首帧期间界面不发生冻结或卡死，加载中途可随时响应返回或切换操作。
2. **后台主界面无冗余重刷**：点击视频卡片进入播放页时，被遮挡的 `Recent` 与 `Library` 页面不在视频打开瞬间触发同步落盘等待与列表重刷；退出播放页返回主界面时，观看记录与进度依然准确更新。
3. **加载过渡与异常提示保持一致**：快速就绪（`300ms` 内）的视频不闪现加载 Spinner，慢速就绪的视频平滑显示加载 Spinner 并在首帧呈现时消失；文件缺失或无法打开时依然准确展示对应的错误提示与空播放器状态。
