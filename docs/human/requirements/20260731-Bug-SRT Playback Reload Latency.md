# 版本
main

# 需求描述
1. 现状：SRT字幕每次加载都有明显体感延迟。
2. 预期：需要优化渲染链路，保证体验上没有明显延迟。

# 修改流程

1. 建立基线并定位耗时
   - 使用包含数百条 Cue 的真实 SRT，分别记录首次打开、跨视频切换、同视频同字幕切换搜索结果的耗时。
   - 分别测量文件读取、解析、全量布局、字形路径生成、当前字幕绘制和主线程回写。
   - 确认优化前的主要耗时阶段，保留数据用于修改后对比。

2. 消除同一 SRT 的重复加载
   - 同一播放会话中，字幕文件和视频画布未变化时，复用已经解析的 Cue、时间索引和布局结果。
   - 切换同一 SRT 文件中的搜索结果时，只更新时间和播放范围，不重新读取、解析或布局整份字幕。
   - 不得因初始时间或准备时间窗口变化而把同一个 SRT 文件识别为新的渲染源。

3. 消除无效重复布局
   - 视频画布尺寸没有变化时不得重新布局。
   - 新字幕源替换过程中，不得为即将废弃的旧字幕启动全量布局。
   - 被替换的解析或布局任务必须及时停止，且不得回写当前播放会话。
   - 快速连续切换结果时，最终只能呈现最后一次选择对应的字幕。

4. 降低 SRT 首次加载成本
   - 行内样式按连续样式区间构造，不再逐字符重复创建字体和富文本对象。
   - 全量布局阶段只计算确定性 Placement 所需的数据。
   - 非当前 Active Cue 的字形描边路径延迟生成；当前 Cue 优先完成并显示。
   - 保持现有 SRT 时间语义、重叠布局、字体回退、描边效果及播放与导出一致性。

5. 根据测量结果处理当前字幕绘制
   - 再次测量当前 Active Cue 的位图生成和主线程耗时。
   - 只有该阶段仍形成明显延迟时，才将位图生成移出主线程，并使用任务代次阻止旧结果回写。
   - 若该阶段已不构成瓶颈，不增加新的异步状态或渲染层。

6. 自动化回归验证
   - 验证同一 SRT 搜索结果切换不会重复读取、解析或全量布局。
   - 验证首次加载、不同 SRT 切换、快速连续切换和任务取消。
   - 验证普通播放、Seek、Current Frame Screenshot、Subtitle Screenshot 和 Collage 的布局结果保持一致。
   - 验证 ASS 加载、渲染、字体、分段缓存和截图路径不受影响。
   - 记录修改前后的分阶段耗时，确认结果支持本需求目标；若测量结果没有改善，停止后续提交并报告。

7. 人工端到端验收
   - 提供可测试构建、修改前后测量结果及重点测试场景。
   - 由需求负责人使用真实 SRT 文件验收首次打开、搜索结果切换、跨视频切换、快速连续切换、Seek 和截图功能。
   - 自动化测试和性能数据通过不代表需求最终验收完成；最终结果以需求负责人的端到端体验验收为准。
