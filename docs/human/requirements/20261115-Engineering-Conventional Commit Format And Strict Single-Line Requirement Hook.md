# 关联设计

- 无。本需求仅更新 Git 提交记录格式规范与本地提交检查拦截规则，不改变任何产品功能或界面表现。

# 需求描述

1. **采用主流小写类型前缀并强制单行纯英文格式**：
   - 提交记录强制仅允许**单行**纯英文半角文本（除 Git 默认注释行外严禁多行正文，严禁出现中文或全角标点），统一格式为 `<type>: <summary> (docs/human/requirements/<requirement>.md)`。
   - `<type>` 仅允许小写前缀 `feat`、`fix`、`docs`、`refactor`、`perf`、`style`、`test`、`build`、`ci`、`chore`、`revert`，禁止附带 `(scope)` 作用域，禁止旧版大写模块前缀。
   - `<summary>` 须为语义明确的精炼英文描述，禁止使用 `update`、`fix`、`changes` 等无意义单字，且禁止在描述正文中裸写 `docs/human/` 路径。

2. **末尾圆括号强制且唯一关联真实需求单**：
   - 不论本次提交是修改代码还是修改文档（含新增/更新需求单、同步设计文档、更新工程文档），行尾圆括号内**仅允许附上唯一一个不带前导斜杠的需求单路径** `(docs/human/requirements/<需求单文件名>.md)`；改动属于文档还是代码统一由前面的 `<type>` 与 `<summary>` 表明，禁止附加 `docs/human/design/` 等其他路径或拼接多个路径。
   - 本地提交检查脚本须同时核验括号内引用的需求单文件在仓库中**真实存在**，文件不存在或拼写错误时直接阻断提交。

3. **历史提交保持原样**：
   - 既有 Git 历史记录不做重写，新规范自本次检查脚本更新落地起对后续所有新提交强制生效。

# 验收标准

1. **工程规范一致无冲突**：相关工程规范文档已同步更新为上述单行小写前缀格式与唯一需求单追溯规则，旧版大写模块前缀及允许附加非需求单路径或正文路径的旧表述已清理完毕。
2. **本地提交检查钩子严格拦截且自测通过**：符合新格式且需求单真实存在的提交正常放行；多行提交、大写前缀、带 `(scope)` 前缀、含非英文半角字符、空洞单字描述、无括号裸写路径、混入非需求单路径或多路径、以及引用不存在需求单文件的提交均被物理拦截并给出清晰报错，配套自测脚本全部通过。
