# SubFinderX - 收藏功能与界面重构迭代设计文档

## 1. 核心需求目标
1. **侧边栏重构**：将现有搜索页重构为 macOS 风格的左侧导航布局，支持展开/收起。
2. **字幕收藏系统**：允许用户通过快捷键 `s` 或右键菜单，将搜索结果或当前播放句子保存到独立收藏夹中。
3. **高亮与状态标识**：列表增加 ⭐️ 标识；支持多层级颜色高亮。
4. **数据持久与同步机制**：索引更新时，收藏条目根据 `srt_path + start_ms + end_ms` 自动同步最新字幕内容。文件丢失时收藏记录保留但不可播放；文件恢复时自动复活。
5. **设置内嵌化**：不再使用独立设置窗口，设置页作为主界面的一部分，由上到下滚动展示。

---

## 2. 已确认的产品决策

### 2.1 交互与信息架构
1. 左侧导航只保留两个主 Tab：`Search`、`Favorites`。
2. `Refresh` 不作为 Tab，改为左下角功能按钮。
3. `Settings` 不再单独打开新窗口，改为左侧导航底部入口；点击后右侧内容区显示设置页面。
4. 主体结构调整为三栏：
   * 左栏：Sidebar
   * 中栏：搜索页 / 收藏页 / 设置页
   * 右栏：视频播放器

### 2.2 收藏行为
1. 收藏的唯一键为 `srt_path + start_ms + end_ms`。
2. `subtitles` 表必须正式新增 `end_ms` 字段，不能只保留字符串形式的 `end_time`。
3. 收藏时 `keyword` 默认应写入当前条目绑定的搜索词快照；若拿不到快照，则允许写空字符串作为统一兜底，不因来源不同做分支处理。
4. `keyword` 不是“最近一次搜索词”，而是“当前这条结果所属的搜索词快照”。
5. 因此在一次搜索结果生成后，需要把该次搜索关键词作为上下文绑定到结果项或结果集，后续从搜索结果点击播放、右键收藏、快捷键收藏，都必须读取这个快照，而不是读取输入框当前值。

### 2.3 收藏页与失效行为
1. 收藏页搜索第一版只匹配 `content`。
2. `is_valid = 0` 时，列表项需要置灰。
3. 失效收藏点击后不播放，弹出 toast：`无法找到对应视频片段。`
4. 右键菜单使用 Flutter `showMenu` 简化实现。

### 2.4 索引同步范围
1. `is_valid` 的更新范围必须限定在“本次参与索引的 source 范围”内，避免误伤其他来源的收藏。
2. 本地路径只处理当前根目录下的收藏记录。
3. WebDAV 路径只处理当前 WebDAV 根路径下的收藏记录。
4. 不在本轮索引范围内的收藏记录，保持原状态，不做推断。

## 3. 数据库层设计

在 `subfinder.db` 中新增 `favorites` 表，并同步扩展 `subtitles` 表结构。`favorites` 必须独立于 `subtitles`，因为 `subtitles` 会在重建索引时按文件重写。

### 3.1 扩展 `subtitles` 表

现有 `subtitles` 表字段不足以支撑稳定收藏同步，因此需要补充：

| 字段名 | 类型 | 说明 |
| :--- | :--- | :--- |
| `end_ms` | INTEGER | 结束毫秒数，用于和收藏做稳定匹配 |

实现要求：
1. 新安装直接按新表结构建表。
2. 老数据库需要迁移：
   * 如果 `subtitles` 已存在但没有 `end_ms`，执行 `ALTER TABLE subtitles ADD COLUMN end_ms INTEGER DEFAULT 0`。
   * 一旦发生该迁移，应用必须触发一次强制全量重建索引，不能等待用户后续再补齐 `end_ms`。
3. 后续所有 `INSERT INTO subtitles` 语句都要写入 `end_ms`。

### 3.2 新增数据表 `favorites`

| 字段名 | 类型 | 说明 |
| :--- | :--- | :--- |
| `id` | INTEGER PRIMARY KEY | 自增主键 |
| `srt_path` | TEXT | 字幕文件绝对路径 / WebDAV 路径 |
| `start_ms` | INTEGER | 起始毫秒数 |
| `end_ms` | INTEGER | 结束毫秒数 |
| `video_path` | TEXT | 对应视频路径 |
| `video_name` | TEXT | 对应视频文件名，便于收藏页直接展示 |
| `content` | TEXT | 收藏时的字幕正文，索引后可被同步更新 |
| `keyword` | TEXT | 收藏时绑定的搜索关键词快照，不允许为空 |
| `is_valid` | INTEGER | 0 或 1；1 表示可播放，0 表示对应资源当前缺失 |
| `created_at` | INTEGER | 收藏时间（Unix 时间戳毫秒） |

约束要求：
1. 建立联合唯一索引 `UNIQUE(srt_path, start_ms, end_ms)`，防止重复收藏。
2. `keyword`、`content`、`video_path`、`video_name` 均设为 `NOT NULL`。
   * 其中 `keyword` 虽允许为空语义，但落库仍使用空字符串 `''`，不使用 `NULL`。
3. `is_valid` 默认值为 `1`。

### 3.3 建议新增索引

为了避免后续收藏页和状态判断变慢，建议增加：
1. `CREATE INDEX idx_favorites_created_at ON favorites(created_at DESC);`
2. `CREATE INDEX idx_favorites_srt_time ON favorites(srt_path, start_ms, end_ms);`
3. 如后续收藏搜索量增大，可再考虑对 `content` 做 FTS；第一版先用 `LIKE`。

## 4. 模型与状态设计

### 4.1 模型层

#### `SubtitleEntry`
需要新增：
1. `endMs`
2. `searchKeywordSnapshot`

说明：
1. `endMs` 来自字幕解析结果，参与收藏与同步。
2. `searchKeywordSnapshot` 不直接入 `subtitles` 表，而是在搜索结果返回后注入到结果对象中。
3. 对于非搜索来源的数据，例如收藏页数据，可以额外映射到统一列表模型，或在 `FavoriteEntry` 中保留 `keyword`。

#### `FavoriteEntry`
新增独立模型，字段至少包括：
1. `id`
2. `srtPath`
3. `startMs`
4. `endMs`
5. `videoPath`
6. `videoName`
7. `content`
8. `keyword`
9. `isValid`
10. `createdAt`

### 4.2 Provider / ViewModel

建议新增以下状态：
1. `homeTabProvider`
   * 当前内容区显示 `Search / Favorites / Settings`
2. `sidebarCollapsedProvider`
   * 控制 Sidebar 展开 / 收起
3. `favoriteSearchKeywordProvider`
   * 收藏页顶部搜索框状态
4. `favoriteResultsProvider`
   * 收藏页结果列表
5. `favoriteIdsProvider` 或 `favoriteLookupProvider`
   * 用于给搜索结果列表快速判断某条字幕是否已收藏
6. `reindexStateProvider`
   * 把刷新状态从 `SearchBarWidget` 中抽出，供 Sidebar 左下角按钮与内容区共用

说明：
1. 现有 `searchKeywordProvider` 继续负责搜索页搜索框。
2. 搜索结果 provider 返回的数据需要带上本次搜索词快照。
3. 任何 Tab 切换都必须主动暂停播放器，包括 `Search`、`Favorites`、`Settings` 之间的所有切换。
4. 列表与播放器间判断“是否为同一句字幕”时，统一使用 `srt_path + start_ms + end_ms` 作为跨数据源身份键，不依赖单表自增 `id`。

## 5. 核心业务逻辑

### 5.1 收藏数据 CRUD (`FavoriteService`)

建议新增独立 `FavoriteService`，至少提供：
1. `addFavorite(SubtitleEntry entry, String keyword)`
2. `removeFavoriteByIdentity(String srtPath, int startMs, int endMs)`
3. `isFavorite(String srtPath, int startMs, int endMs)`
4. `getFavoriteIdsForEntries(List<SubtitleEntry> entries)`
5. `searchFavorites(String? filterKeyword)`
6. `watch` 或 `invalidate` 相关 provider 的辅助方法

具体规则：
1. 添加收藏时：
   * `keyword` 优先取 `searchKeywordSnapshot`
   * 若拿不到，则写入空字符串 `''` 作为统一兜底
   * `is_valid = 1`
   * `created_at = DateTime.now().millisecondsSinceEpoch`
   * 使用 `INSERT OR IGNORE` 或先查重后插入
2. 删除收藏时：
   * 无论是在搜索页、收藏页，还是通过快捷键 `s`
   * 删除前都必须弹出 `AlertDialog` 二次确认
3. 收藏页搜索：
   * 如果搜索词为空，返回全部收藏
   * 如果不为空，使用 `WHERE content LIKE ?`
   * 默认按 `created_at DESC`

### 5.2 搜索结果关键词快照

这是本次迭代里很关键的一条规则。

要求：
1. 一次搜索执行时，结果集中的每个 `SubtitleEntry` 都要绑定“本次搜索词快照”。
2. 后续无论用户是否又输入了新关键词、清空了输入框、做了别的搜索，只要当前播放句子来自这次结果集，就仍然使用当时那次搜索词做收藏。
3. 因此播放器快捷键 `s` 不能直接读取搜索输入框当前值，而应读取 `activeSubtitleProvider` 中该条目的 `searchKeywordSnapshot`。

### 5.3 重建索引时的自动同步 (`IndexerService` 修改)

在每次完成一个 source 的索引后，执行该 source 范围内的收藏同步：

1. **更新内容与复活**
   * 对当前 source 范围内的 `favorites`，按 `srt_path + start_ms + end_ms` 与 `subtitles` 匹配
   * 匹配成功后：
     * `favorites.content = subtitles.content`
     * `favorites.video_path = subtitles.video_path`
     * `favorites.video_name = subtitles.video_name`
     * `favorites.is_valid = 1`

2. **标记丢失**
   * 仅对当前 source 范围内的 `favorites`
   * 如果在当前 `subtitles` 中找不到同一 `(srt_path, start_ms, end_ms)`，则将其 `is_valid = 0`

3. **禁止全表误伤**
   * 不能把不属于当前 source 的 favorites 一并置灰
   * 否则多根目录 / 多 WebDAV 场景下会误判

### 5.4 source 范围判定策略

#### 本地路径
1. 假设本轮索引根目录为 `/Volumes/Media/A`
2. 只同步 `favorites.srt_path` 位于该目录内的记录
3. 可通过路径前缀或 `path` 包判断

#### WebDAV 路径
1. 使用当前 WebDAV 根 URL 作为逻辑范围
2. 只同步 `favorites.srt_path` 属于该根路径的记录
3. URL 范围判断必须先经过统一规范化函数处理，再做前缀比较
4. 该规范化函数至少需要：
   * 去除 userInfo（用户名密码）
   * 去除末尾斜杠
   * 保持与索引器写入 `srt_path` 时一致的 path 比较规则
5. 禁止在不同模块中各自实现一套不一致的 WebDAV 路径比较逻辑

## 7. 列表项与高亮实现

### 7.1 通用列表组件改造

建议把现有 `ResultListWidget` 改造成可复用的统一列表组件，支持两种数据源：
1. 搜索结果
2. 收藏结果

建议能力：
1. 传入列表数据
2. 传入当前高亮词
3. 传入收藏关键词
4. 传入是否已收藏
5. 传入是否可播放
6. 传入点击回调
7. 传入右键菜单行为

### 7.2 多层级高亮渲染

重构当前 `_buildHighlightedText` 为独立高亮组件或独立工具方法。

优先级：
1. 当前搜索词 `currentKeyword`：黄色高亮
2. 收藏关键词 `savedKeyword`：浅蓝色高亮
3. 普通文本：默认样式

规则：
1. 当前搜索词优先级高于收藏关键词
2. 如果两个关键词发生重叠，优先渲染当前搜索词
3. 第一版仅做大小写不敏感匹配，不做更复杂的分词逻辑

### 7.3 列表状态标识

1. 若当前条目已收藏，在左上角绘制 ⭐️
2. 若当前条目为选中播放态，沿用现有左侧高亮边框
3. 若当前条目 `is_valid = 0`：
   * 文本颜色置灰
   * 视频名与时间戳一并置灰

### 7.4 右键菜单

使用 Flutter `showMenu` 实现：
1. 未收藏：显示“收藏”
2. 已收藏：显示“移除收藏”
3. 点击“移除收藏”前弹出确认框

## 8. 播放器快捷键与反馈

### 8.1 `s` 键行为

在 `VideoPlayerPane` 中新增 `s` 键拦截逻辑：

1. 读取 `activeSubtitleProvider` 当前条目
2. 如果没有激活条目，不做任何事
3. 检查该条目是否已收藏

#### 未收藏
1. 读取该条目的 `searchKeywordSnapshot`
2. 若为空，直接中止并提示错误
   * 正常实现下不应发生；这里属于兜底保护
3. 写入收藏
4. 刷新收藏状态 provider
5. 通过 `ActionFeedbackOverlay` 弹出收藏成功反馈

#### 已收藏
1. 如果播放器当前正在播放，先 `pause()`
2. 弹出确认框：`确定要移除对该句子的收藏吗？`
3. 确认后删除收藏
4. 刷新收藏状态 provider
5. 通过 `ActionFeedbackOverlay` 弹出取消收藏反馈

### 8.2 Toast / 浮层反馈

第一版统一采用现有浮层能力扩展实现，不单独引入原生 toast。

建议覆盖三类反馈：
1. 收藏成功
2. 取消收藏
3. 无法找到对应视频片段

说明：
1. 这部分不是本次架构重点，先实现可用版本
2. 若后续视觉体验不满意，再单独迭代 toast 样式
3. 所有删除确认弹窗都在整个 App 主界面中间弹出，不绑定到局部小窗或右键菜单位置
